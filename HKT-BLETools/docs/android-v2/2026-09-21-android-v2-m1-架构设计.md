# Android v2 · M1 架构设计

> 状态：✅ 2026-09-21 依据 iOS 实测架构（探索报告）+ M0 裁决产出
> 上游文档：[M0 裁决与功能对照](2026-09-21-android-v2-m0-裁决与功能对照.md)；蓝本：`ios/Package.swift` + `ios/Sources/*` + `ios/App/*`

## 1. 模块结构（Gradle 多模块）

```
settings.gradle.kts:
  include(":app", ":core-protocol", ":core-device", ":core-ota", ":core-ble", ":designsystem")

依赖（单向，禁止循环——对应 iOS SwiftPM 依赖图）：
  :core-protocol ← （无依赖，纯 Kotlin JVM）
  :core-device   ← :core-protocol
  :core-ota      ← :core-protocol
  :core-ble      ← :core-protocol
  :designsystem  ← （无依赖；Compose + 主题 Token）
  :app           ← 上面全部
```

- `:core-*` 四个模块 = `kotlin("jvm")` 纯 JVM 模块：**零 Android 依赖**，单元测试 JVM 直跑（秒级、不碰模拟器）——对应 iOS SwiftPM 包的可测性核心。
- `:designsystem` / `:app` = Android 模块（Compose）。SystemCentral（真蓝牙）、MockCentral、DemoResponder、页面都在 `:app`——与 iOS「SystemCentral 在 App target、包只含纯逻辑」完全同位。
- JVM 工具链 17（本机 AS JBR 已验证）；minSdk 26 / compileSdk 34 保持。

## 3. iOS → Kotlin 类型映射表（逐类型）

### 3.1 :core-protocol（← ios/Sources/CoreProtocol）

| iOS | Kotlin | 映射要点 |
|---|---|---|
| `HKTFrameEncoder`（enum 静态方法） | `object HKTFrameEncoder` | `Data`→`ByteArray`；appFrame/fillerPayload/powerPayload/udsConfigPayload/dcConfigPayload/svcConfigPayload/svcRealtimeTaskPayload/svcTimedTaskPayload/svcDeleteTaskPayload/timeSyncFrame 一一对应；`CommandCode`→`enum class`（0x01/02/03/04/05/06/FD/FE/FF） |
| `HKTResponseParser` + `TLVSizeTable` | `object HKTResponseParser`（internal size table） | `parse(bytes, family): Parsed(entries, unknownTail)`；未知类型→`unknownTail=true`（无长度字节不可跳过）；前缀/截断→`Result.Failure(ParseError)` |
| `TLVEntry` / `DeviceFamily` / `BEValue` | data class / enum class / value class 组 | `BEValue.u16/u24/u32/i16/i24/i32/mag31`——**mag31=GPS 符号位幅值非补码**，逐位移植+向量锁定 |
| `DeviceSnapshot`（struct ~40 字段）+ `DeviceSnapshotDecoder` | `data class DeviceSnapshot` + `object DeviceSnapshotDecoder` | 字段一一对应 |
| `CRC16` | `object CRC16` | KERMIT（poly 0x8408 反射，init 0）——以现有 CRC16.kt 为底，向量 abc→58E9 锁定 |
| `SignedValueDecoder` | `object SignedValueDecoder` | 符号位减模规则（>0x8000/0x800000/0x80000000） |

### 3.2 :core-device / :core-ota

| iOS | Kotlin | 映射要点 |
|---|---|---|
| `DeviceRegistry` + `DeviceProfile` + `DeviceCapability`（9 值） | 同名 object/data class/enum class | UDS100→uds100；DC200/EPS100/MPS100→dc200Family；SVC100→svc100；`match` 精确 + `matchBroadcast` 包含式；未知名永不连接 |
| `OTATransferPlanner` + `OTAACK` | `object OTATransferPlanner` + `data class OtaAck` | 128B 分包/末包补 FF/`forceFlush`(cmd=0xFF)/finishFrame(cmd=3)/ACK(14B) 解析 |
| `OTAEngine`（@MainActor @Observable class） | `class OtaEngine(scope: CoroutineScope)` | 状态 `StateFlow<OtaState>`；`bind(sender)`/`begin()`/`handle(bytes): Boolean`/`cancel()` 同名；节拍用 `scope.launch { delay() }` 替代 Swift Task |

### 3.3 :core-ble

| iOS | Kotlin | 映射要点 |
|---|---|---|
| `BluetoothPort`（protocol，7 方法） | `interface BluetoothPort` | activate/startScan(options,onUpdate)/stopScan/connect(events)/cancelConnect/disconnectDevice/makeLink；**回调契约=Main dispatcher 投递**（对应 iOS「回调主线程投递」，SystemCentral/MockCentral 两端共同遵守） |
| `PeripheralLink`（protocol） | `interface PeripheralLink` | `send(bytes)` + `var onReceive: ((ByteArray) -> Unit)?` + `var onDisconnected: (() -> Unit)?` |
| `ScanOptions.isListable` | `data class ScanOptions` | 入列规则（RSSI+前缀+非空名）唯一出处，真/假蓝牙源共用 |
| `DiscoveredDevice` / `ConnectEvent` / `HKTProfile` | data class / sealed class / object(UUID 常量) | HKT 服务/写/Indicate UUID 与安卓现值一致 |
| `ConnectOrchestrator`（@MainActor @Observable） | `class ConnectOrchestrator(scope)` | 三阶段 budgets 10s/5s/5s；`phase: StateFlow<ConnectPhase>`；begin() 先于 port.connect() 的顺序契约保持 |
| `DeviceSession`（@MainActor @Observable） | `class DeviceSession(scope, family, deviceName, link, pollInterval)` | 快照 `StateFlow<DeviceSnapshot?>`；`sendWrite`/`sendRawAwaitingAck`/`startCalibration`/`sendTimeSync` = suspend fun；**先注册 ACK 等待再发送**的顺序契约保持；`setPollingSuspended`/`rawFrameHandler` 同名 |
| `BLEAvailability` | enum class 五态 | |

### 3.4 :app（← ios/App）

| iOS | Kotlin | 映射要点 |
|---|---|---|
| `SystemCentral`（CBCentralManager 委托） | `class SystemCentral : BluetoothPort, PeripheralLink` | Nordic scanner + BluetoothGatt；内部线程→`Handler(Looper)` 收发，回调切 Main；MTU 协商、发现服务、订阅 Indicate 三段上报对齐现网 BLEUtils 语义 |
| `MockCentral` / `MockLink` / `DemoResponder` / `DemoLaunch` | 同名 | `-mockble` 启动参数→Shell 注入或 debug 构建开关；MOCK_* 环境变量→`System.getenv`/BuildConfig 演示旋钮 |
| `ScanModel` / `ConnectModel` / `ValveTaskStore` / `LogStore` / `LanguageStore` / `FeatureSurface` | 同名类（StateFlow 驱动） | 组合根=`HktApp : Application`；构造注入 `port: BluetoothPort`（真/Mock 切换点） |
| SwiftUI 页面 ×13 | Composable ×13 | P-01 扫描/P-02 覆盖层/P-03 详情/P-03b 技术/P_config/P-tasks/P_cal/P_ota/P-07 设置+日志/P_privacy/P-08 门/LocateFlow/CameraScanner(ZXing 版) |
| `DesignSystem`（Theme + 40 组件） | `:designsystem` Composable 同名同参数 | Token=原型 CSS（色板/圆角 10/8/18/字号阶梯/padding 13/14），与 iOS Theme.swift 同源 |
| NavigationStack | navigation-compose | 栈式导航+返回驻留语义（R-31/R-32） |

## 4. 并发模型映射

| iOS | Android v2 | 契约 |
|---|---|---|
| `@MainActor @Observable` | 主线程 StateFlow + Compose 收集 | 模型状态只在主线程写 |
| `Task` / `Task.sleep` | `scope.launch` / `delay`（(scope 由构造注入，测试用 StandardTestDispatcher) | |
| `CheckedContinuation` + 超时 Task | `suspendCancellableCoroutine` + `withTimeout` | ACK 等待取消安全（iOS 修过的取消竞态防复发） |
| 回调主线程投递 | 回调 Main dispatcher 投递 | BluetoothPort/PeripheralLink 双实现共同契约 |
| `@Sendable` 闭包 | 普通函数类型（单线程约束由契约保证） | |

## 6. 迁移顺序与「旧 UI 共存」策略

1. **M2**：升级+骨架。期间 `:app` 旧代码（4 Activity/XML/Communicate 全局态）**原样保留、保持可构建可安装**（分支内随时可出验证包）。
2. **M3**：`:core-*` 移植+金向量全绿（旧链路不动——新旧并存互不引用）。
3. **M4**：`:core-ble`+SystemCentral/Mock/演示基建+会话测试绿。此时新协议栈就绪但尚未接 UI。
4. **M5–M6**：单 Activity Compose 化——`MainActivity` 改造为 Compose 宿主，按 P-01→…→P-08 逐页替换，**替换一个删一页旧代码**；M6 完成时旧 XML/Communicate 全局态/4 Activity 结构全部删除，`-mockble` 演示模式贯通全 UI。
5. **M7–M8**：真机验证清单 + v4.0 收尾。

> 澄清：M0 计划中「M4 后模拟器全 UI 可跑」的准确含义 = 新栈 M4 就绪、M6 UI 替换完成后兑现。
