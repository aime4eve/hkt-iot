## 1. 目标与边界

UI 设计是 iOS v1 功能开发的强制前置阶段（需求 §3.3）：未经 UI 设计基线评审通过，不得开始 SwiftUI 功能页面实现。

本计划覆盖：

1. 信息架构与导航关系。
2. 页面清单及每页的状态集（不允许"加载中/失败"空白描述）。
3. 关键用户流程（扫描、连接、状态、OTA 成功/失败/恢复）。
4. OTA 全生命周期界面规范。
5. 设计 Token 与可复用组件。
6. 中英文本地化与设计验收清单。

设计稿假定基线（随裁决闭合更新）：iOS 17+、iPhone XS/XR 起、仅 iPhone、中英双语、浅色/深色双外观（见[待确认项 Q5/Q6/Q10](2026-09-03-ios-v1-open-items-recommendations.md)）。

## 2. 信息架构

导航采用「单列表栈 + 全局设置」结构，与单连接/单设备会话模型一致，不引入 Tab：

```text
App Root
├── 设备列表页 P-01（首页 / 扫描）
│   ├── [连接过程] 连接状态覆盖层 P-02（sheet / overlay，非独立页）
│   └── 设备详情页 P-03（会话内）
│       ├── 固件升级页 P-04（OTA 全生命周期）
│       ├── 参数配置页 P-05（M8，FeatureSurface 控制，v1 主线为禁用占位）
│       └── Debug 页 P-06（隐藏入口进入）
└── 设置页 P-07
    ├── 语言 / 关于（About）
    ├── 诊断日志
    ├── 扫描过滤设置（RSSI 阈值 / 过滤无名称设备）
    └── [隐藏入口：连点版本号 7 次] → Debug 模式开关 → P-06

全局拦截层：权限与蓝牙状态引导 P-08（全屏覆盖，非导航页）
```

导航规则：

1. P-01 → P-03 的唯一入口是点击列表中的支持设备。
2. P-03 → P-04 后进入 OTA 过程时启用返回保护（见 §5）。
3. P-06 仅经隐藏入口可达，`dev` 构建默认开启入口。
4. 任何页面在蓝牙权限被拒/蓝牙关闭时，由 P-08 全局接管。

## 3. 页面清单

每页状态均映射到架构大纲 §9 的 ViewModel 状态（评审时逐项核对）。

### P-03b 技术参数页（DC200Family 专属，2026-09-07 新增；原型已实现）

工程诊断视图：整合地磁 X/Y/Z 三轴实时值与雷达 10 段频谱柱状图，附当前判定对照（车位状态/工作模式），数据随轮询每秒刷新。用于现场从技术参数角度定位地磁/雷达问题（三轴变化量过小=灵敏度/安装异常；频谱整体偏低=遮挡/干扰）。本页豁免“不出现协议术语”规则，可显示原始数值；仅 DC200Family 提供入口。

| 追溯 | UX-TECH-001；FR：需求 §7.2；FW-REF：TLV 0x5D/5E/5F/0x60；R-27/SP-27 |

### P-04 固件升级页（OTA）

OTA 是 v1 强制能力，页面按六阶段设计，任一阶段都有界面反馈、禁止操作与错误恢复路径（需求 §8.3）：

| 阶段 | 界面反馈 | 用户可执行动作 | 禁止/保护 |
| --- | --- | --- | --- |
| ① 选择固件 | 文件选择器入口；已选文件名 + 大小 + 期望版本（预填可编辑） | 选择/更换文件；修改期望版本 | 未选有效文件时"开始升级"禁用 |
| ② 确认 | 确认弹窗：设备型号、目标文件、当前版本 → 期望版本；提示"升级期间请保持 App 前台、勿断开设备" | 确认 / 取消 | 确认前显示返回保护说明 |
| ③ 传输中 | 进度百分比 + 已传包数/总包数 + 阶段文案 | 取消（中断提示不可逆风险） | 返回保护弹窗；升级入口置灰 |
| ④ 完成包/等待重启 | 阶段文案："数据发送完成，等待设备重启"；进度条停在 100% 但明确标注"尚未完成" | 等待 / 取消 | 同上 |
| ⑤ 重新广播/重连 | 阶段文案 + 等待动画；显示已等待时长 | 等待 / 重试 / 取消 | 超时给出重试引导 |
| ⑥ 版本确认 | 自动比对期望版本 | — | — |
| 结果-成功 | 明确成功页：新版本号 + 全程耗时 + 升级报告（升级前后版本、各阶段耗时，可导出存档） | 完成 → 返回 P-03 | — |
| 结果-失败 | 失败页：失败阶段 + 原因（人话，不用协议术语）+ 重试入口 | 重试 / 返回 | — |

异常场景映射（需求 §8.5 十项 → 页面状态）：非预期/空文件→①的文件校验错误；读取失败→①；BLE 断开→④/⑤ 中断为"连接丢失"失败态；App 进后台返回→恢复当前阶段并提示；用户返回→返回保护弹窗；蓝牙关闭→失败态引导开启；设备无响应→阶段超时失败；未重新广播→⑤ 超时；重连失败→⑤ 重试；版本读取失败→⑥ 失败可重读。

| 追溯 | UX-OTA-001~006；FR：需求 §8；FW-REF：各固件 `Compents/BootLoader/uart.c`；A-07/A-08 |
| --- | --- |

### P-05b 阀门任务页（SVC100 专属，2026-09-06 用户确认进 v1；原型已实现）

| 内容 | 说明 |

## 4. 关键用户流程

| 编号 | 流程 | 覆盖页面 |
| --- | --- | --- |
| F-01 | 扫描 → 过滤 → 点击设备 → 连接 → 进入详情 | P-01→P-02→P-03 |
| F-02 | 详情页状态轮询展示（含轮询无响应降级） | P-03 |
| F-03 | OTA 正常成功全流程（选择→确认→传输→重启→重连→版本确认→成功） | P-04 |
| F-04 | OTA 失败与恢复（断开/超时/蓝牙关闭/版本不符 → 失败页 → 重试） | P-04 |
| F-05 | 会话中断开与重连（异常断开提示 → 返回列表或原地重连） | P-03/P-01 |
| F-06 | 权限拒绝 / 蓝牙关闭的引导与恢复 | P-08 |
| F-07 | 语言切换即时生效（含 OTA 页阶段文案） | P-07 + 全局 |
| F-08 | 隐藏入口开启 Debug 模式 → 原始命令收发 | P-07→P-06 |

线框阶段必须先过 F-03/F-04（OTA 是 v1 核心价值），再过 F-01/F-05。

## 5. 交互规范要点

1. **返回保护**：OTA 阶段③④⑤ 中返回必须弹确认，明示"中断可能导致设备升级失败"。
2. **重试策略**：连接/重连/版本读取失败提供显式重试按钮；重试不重置已完成的 OTA 阶段描述。
3. **禁用条件**：未连接禁用全部操作入口；升级中禁用配置与再次升级入口。
4. **确认弹窗**：升级确认（Q8 期望版本）、Debug 发送、删除日志。
5. **术语**：界面不出现 `0xFF`、TLV、CRC、MTU 等协议术语（需求 §3.3 验收标准 5）；Debug 页除外（面向工程人员，展示原始 hex）。
6. **可访问性**：所有文本支持 Dynamic Type；状态除颜色外辅以图标/文字（色弱可用）。

### 5.1 错误分类 → 页面状态映射（需求 §10.2 十类，评审 P1-5 补齐）

每类错误必须落到具体页面状态并附带建议动作，禁止无落点的"统一失败"：

| 错误分类 | 页面状态落点 | 建议动作示例 |
| --- | --- | --- |
| 用户输入错误 | P-04 阶段①/P-05 表单内联提示 | 修正输入（附固件边界提示） |
| 权限错误 | P-08 权限被拒态 | 跳系统设置开启 |
| 蓝牙不可用 | P-01 状态③④、P-08 | 开启蓝牙 / 换支持 BLE 的机型 |
| 连接错误/超时 | P-02 状态②③ | 重试 / 返回列表 |
| 服务或特征缺失 | P-02 状态④ | 检查设备固件，重试连接 |
| 写入失败 | P-06 发送失败态、P-04 传输失败态 | 重试 / 重新连接 |
| 协议 CRC 错误 | P-06 流水标记、P-04 失败态（疑似丢帧） | 重试该操作 / 重连 |
| 响应格式错误 | P-03 状态②b 数据异常态（错误横幅 + 保留上次有效值） | 重连 / 导出诊断日志 |
| OTA 文件错误 | P-04 阶段①文件校验失败 | 重新选择固件文件 |
| OTA 超时/无响应 | P-04 对应阶段超时失败态 | 按阶段给出重试/重刷引导 |

## 7. 本地化计划

1. 采用 String Catalog（`.xcstrings`），key 规范 `<feature>.<screen>.<element>`，如 `ota.stage.waitingReboot`。
2. 首版语言：简体中文、English；文案表在设计稿评审时同步产出（中英对照列）。
3. OTA 六阶段、错误分类（需求 §10.2 十类）、设备字段名、单位全部纳入本地化；禁止 view 内硬编码。

## 10. iOS 相对 Android 的优势目标

产品约束：iOS v1 整体优于 Android 版。优势判据是"现场更可靠、失败更可解释、OTA 更可信、迭代更快"，**不是功能更多**——v1 功能广度仍按 §3 页面清单与 FeatureSurface 裁剪，不为"追赶功能清单"扩面。

| 维度 | 差异项 | Android 现状 | iOS v1 设计 | 状态 |
| --- | --- | --- | --- | --- |
| 可靠 | 并发与会话 | 后台线程 + BLE 回调无锁读写全局状态（CLAUDE.md 已记载风险） | actor 单 owner + 快照链路（架构大纲 §4） | 已内建 |
| 可靠 | 断开处理 | 断开后 UI 状态易失真 | 连接状态机、预期/异常断开分类、重连引导（P-03 状态③） | 已内建 |
| 可解释 | 错误呈现 | 接近统一"失败" | 错误十分类，每类人话文案 + 建议动作（P-04/P-08 错误态） | 已内建，本次升级为验收项 |
| 可解释 | 状态健康度 | 原始字符串直出 | 字段卡片 + 单位 + "最后更新时间"，轮询失败降级显示最后有效值（P-03 状态②） | 已内建 |
| OTA 可信 | 成功判定 | 进度条 + 人工观察 | 重启→重广播→重连→版本比对闭环；100% 明确标注"尚未完成"（P-04 阶段④） | 已内建 |
| OTA 可信 | **升级报告** | 无 | 每次 OTA 生成摘要（前后版本、各阶段耗时、失败原因），一键导出存档，现场支持/验收留痕 | **本次新增（v1 亮点）** |
| OTA 可信 | 防呆 | 弱 | 返回保护、后台往返恢复、蓝牙关闭引导、文件/期望版本安全网（P-04） | 已内建 |
| 迭代快 | 质量基线 | 仅 1 个单元测试类 | CRC/帧/TLV/分包/OTA 状态机测试矩阵，双端共享向量 | 已内建 |
| 体验 | 视觉与可访问性 | 无成体系设计系统 | 设计 Token、深色模式、Dynamic Type、双语即时切换（D3–D5） | 已内建 |

不建议为"优于 Android"引入的项（scope 护栏）：参数配置全量 UI 与二维码提前进 v1、后台/锁屏 OTA、Watch/小组件/桌面快捷、Excel 导出照搬（Android 该能力本就是死代码）。以上均待 v1 后按裁决开放。
