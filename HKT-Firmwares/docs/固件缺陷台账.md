# 固件缺陷台账

in-house 全部固件工程发现的缺陷**统一记录于此**，是缺陷状态的唯一权威来源。无论缺陷由哪条线发现（App 联调、协议审计、解码器平台、现场反馈），一律记到这里，其他文档（如 `HKT-BLETools/shared/devices/firmware-traceability.md`）只保留契约事实与指向本台账的引用。

## 记录规则

- **ID**：`FD-NNN` 全局流水号（不按项目分段，跨项目缺陷一条即可）。
- **状态**：`OPEN`（待修）→ `FIXED`（源码已改，注明待随哪个版本发布/已验证）→ 也可判 `BY-DESIGN`（行为如此，非缺陷）或 `WONTFIX`（不修，写明理由）。
- **每条必填**：现象、根因（固件源码 `文件:行号` 证据）、影响版本范围、发现途径、修复建议；修复后补 验证方式与日期。
- **严重度**：高=现网数据/功能错误且无绕行；中=功能错误但有绕行或影响面窄；低=边缘场景。
- 改动本台账随代码/文档一并提交 Git；固件组修复后在对应条目回填修复提交与版本。

## 明细

### SVC100（LoRaWAN_Solenoid_Valve_Controller）

#### FD-001 · 0x03 实时任务脉冲 3B 超读

- **提出**：2026-09-06（iOS 协议里程碑核对，App 发 100 设备实得 ~25787）
- **现象**：实时任务下发的脉冲计数实际值 = `(发送值 << 8) | CRC高字节`。
- **根因**：`data[5]==7 && data[6]==3` 分支按 3B 读脉冲（`srcHex[5]<<16|srcHex[6]<<8|srcHex[7]`），第 3 字节实为 CRC 高位。两处：BLE 入口 `SVC communicate.c:1660`、共享分发 `communicate.c:556`。
- **修复**：2026-09-09 固件组确认，两处均改 2B 读（`srcHex[5]<<8|srcHex[6]`），len 门槛 7 不动（改 8 会挡死安卓现网帧）。**待随下一版固件发布后在真机回归**。
- **App 契约**：不变，仍发 6B 载荷（`TX-SVC-TASK-001`，与 Android V3.21 逐字节一致）。

### UDS100（LoRaWAN_Ultrasonic_Distance_Sensor）

#### FD-002 · hkt 0x06 对时帧死代码（与 DC200 家族同源）

- **提出**：2026-09-11（协议审计）
- **现象**：App 按安卓同款 hkt 0x06 对时帧发送，设备永不响应（无 ACK、不生效）。
- **根因**：0x06 分支的内层守卫 `data[5]==4 && data[6]==6` 嵌套在外层 `data[5]==5||9`（UDS `UDS-comm:1183` vs `:1280`）之内被遮蔽，帧永远到不了分支。
- **影响**：hkt 对时在 UDS100/DC200 家族不可用。绕行：UDS100 走 ASCII `syncDeviceTimestamp:<unix>`（无 ACK、固定 UTC+8，`UDS-comm:1093`）；DC200 家族 ASCII 路径另有 FD-003，故 App 直接禁用 DC 对时。
- **修复建议**：放宽外层门禁或把 0x06 分支提级到与 0xFF 查询同层；或正式宣布 hkt 对时仅 SVC 支持，App 保持绕行。

#### FD-004 · 写命令与 1Hz 查询在设备单 RX 缓冲上互相挤撞（无 ACK 静默丢失）

- **提出**：2026-09-20（iOS 真机联调，探针日志取证；同根因早前已在配置页发现并缓解）
- **现象**：写命令（0x02 配置 / 0xFE 开关机 / 0xFD 校准）紧邻查询应答窗口发送时被整帧丢弃——设备无 ACK、无动作；重试或停轮询后同一帧即成功。实测：UDS100 开机首击失败 ×2 轮、关机首次失败后重试成功、0xFD 即发 ACK 修复前常丢。
- **根因**：设备 RX 单缓冲 + 50ms 空闲判帧（`uart.c:315`），且查询处理阻塞数百 ms（UDS 回调含测距/ADC）。App 按安卓节奏 1Hz 轮询时，写帧极易拼进未消费的缓冲，只有最前帧被分发。
- **App 缓解（已上线并真机验证）**：配置页、校准全程、开关机写窗口内停轮询（`setPollingSuspended`；提交 95d0f95 / a560368）。校准修复后 0xFD 立即 ACK 与 "Calibration Done" 完成文本一次到位（探针实证 2026-09-20）。
- **固件侧建议（OPEN）**：RX 帧按 SYNC_HEAD 分段分发而非整缓冲覆盖，或写命令入队主循环延迟处理；修好后 App 可收回停轮询窗口。
- **⚠️ 安卓佐证（安卓 App 自身缺陷，勿参照）**：`streamDevice(0xFE,…)` 载荷恒为 `FFFFFFFF`（开机/关机同一帧，`data[10]=0xFF` 不匹配任何分支）——安卓的 UDS100 开关机从未真正改变设备状态，只是把无条件 ACK 当成功。

### DC200 家族（LoRaWAN_ParkingSensor：MPS100 / EPS100）

#### FD-003 · ASCII 对时月份 +1

- **提出**：2026-09-11（协议审计）
- **现象**：ASCII 对时后设备月份比实际快 1 个月。
- **根因**：ASCII 对时路径写入 `tm_mon+1`（`DC communicate.c:1014`）。`timeP->tm_mon` 本身语义与 RTC 期望的换算在服务器同步路径（`:994`）是正确的，仅 BLE ASCII 路径多加。
- **影响**：DC200 家族 BLE 对时不可用。绕行：App 已禁用 DC 对时（界面不出现该入口）。
- **修复建议**：对齐 `:994` 的服务器同步路径写法。
