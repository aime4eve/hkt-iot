## 2. 必须先修的 P0

### P0-1 FIFO 时序预算分解算术错误

第 5.4 节验收标准写明：

- 主循环任一任务步进连续占用 `<= 150 ms`
- EXTI 置位后批处理等待 `<= 150 ms`
- 批处理本身 `< 100 ms`
- 合计 `< 280 ms`

三项相加是 `400 ms`，不是 `280 ms`。这不是测试余量问题，而是预算表自身无法通过算术校验；按该分配实现必然存在 FIFO overrun 风险。

**修改建议**：

1. 将预算改为严格求和，并为采样抖动、中断响应和测量误差保留余量。
2. 示例：任务占用 `<= 50 ms`、EXTI 等待 `<= 100 ms`、批处理 `< 100 ms`，合计 `<= 250 ms`，对 25 Hz 的 280 ms 理论上限保留 30 ms 余量。
3. 验收红线建议写成“25 Hz 实测中断到批处理完成 `< 250 ms`，理论上限 280 ms 不得触碰”。
4. 对 I2C 失败重试、Flash 步进、GPS 解析等任务同时发生的情况做最坏预算，而不是只约束单任务名义耗时。

### P0-2 50 Hz 诊断模式的 watermark 25 配置不安全

设计允许 `active_sampling_rate_hz = 50 Hz` 临时诊断模式，但 watermark 仍沿用连续 25 Hz 的 25 级配置，并沿用 280 ms 硬时限。

FIFO 深度为 32 级。watermark 25 触发后仅剩 7 级：

- 25 Hz：`7 / 25 = 280 ms`
- 50 Hz：`7 / 50 = 140 ms`

因此 50 Hz 下 280 ms 预算已超过 FIFO 充满时间，设计目前只把 50 Hz 排除在电池验收外，没有排除在功能与 FIFO 稳定性验收外。

**修改建议**：

1. 将 watermark 和硬时限定义为随采样率变化的公式：`deadline = (32 - watermark) / rate`。
2. 50 Hz 诊断模式不得沿用 watermark 25；建议使用 watermark 12 或 16：
   - watermark 12：余量 `20 / 50 = 400 ms`
   - watermark 16：余量 `16 / 50 = 320 ms`
3. 50 Hz 诊断模式单独设置实测红线，例如“中断到批处理完成 `< 250 ms` 或 `< 280 ms`，取决于最终 watermark”。
4. 测试计划增加 50 Hz 诊断模式连续运行用例，验收 FIFO overrun 为 0。
5. Flash 写入时序中的“批处理后约 900 ms 以上”也需按当前采样率重算；50 Hz、watermark 12/16 时下一次批处理会明显早于 25 Hz 场景。

## 3. 开工前应闭环的 P1

### P1-1 “INT2 = FIFO watermark”路由方案与 LIS3DH 能力不符

V1.3.1 的优先方案写为：

- INT1 = AOI
- INT2 = FIFO watermark

但当前 LIS3DH 驱动和数据手册语义均显示 FIFO watermark 只能通过 `CTRL_REG3.I1_WTM` 路由到 INT1：

- `lis3dh_types.h` 标注 `lis3dh_int_fifo_watermark` 为 only INT1。
- `lis3dh_enable_int()` 对 watermark 只写 `ctrl3.I1_WTM1`。
- `FIFO_CTRL.TR` 的 trigger 参数只用于 Stream-to-FIFO 触发选择，不是 watermark 引脚路由。

因此“watermark 路由到 INT2”的优先方案按当前芯片语义无法实现。文档中的单脚回落方案反而是可行路径。

**修改建议**：

1. 将单 INT1 多事件方案定为主方案：`I1_IA1 + I1_WTM` 同路由 INT1，读 `INT1_SRC` 与 `FIFO_SRC` 区分。
2. 删除或降级“INT2 = FIFO watermark”方案。
3. 若原理图确认 INT2 可用，物理分脚方案应反向设计：INT1 = FIFO watermark，INT2 = AOI1（通过 `CTRL6.I2_AOI1` 路由），而不是当前写法。
4. 同步修改第 12 章驱动改动和第 13.2 节路由测试期望。

### P1-2 `0xB1 Delay` 字段量程不足，无法支撑长时间补报

`Delay` 为 `uint8`，有效范围仅 `1~254` 分钟，超过后返回 `0xFF` 时间未知。当前告警缓存深度按 10 分钟静默期可覆盖约 80 分钟，但网络失败可能持续数小时或更久；一旦超过 254 分钟，平台无法还原事件时间。

这与第 15.3 节“延迟补报能还原事件发生时间”的无条件验收红线冲突。

**修改建议**任选其一：

1. 改为 `uint32` UTC 秒级事件时间戳，并定义时间未同步时的无效值。
2. 改为 `uint16 delay_minutes`，并显式限制可换算范围为 `0~32767` 分钟；`0xFFFF` 表示未知。该范围与 `uint32_t ms_uptime` 的 `< 2^31 ms` 前提一致。
3. 如果坚持 254 分钟上限，必须把“超过后时间不可还原”写入需求和验收，不能同时承诺无条件还原事件时间。

### P1-3 10 分钟默认周期缺少存量配置迁移策略

设计将 10 分钟定位与上报作为默认和功耗验收口径，但现有固件持久化调度配置默认为 30 分钟，且新 ACC 配置区无法判断旧运行调度是否已经迁移。升级后若读取到合法的旧 30 分钟配置，新固件实际仍按 30 分钟运行，V1.3.1 未定义这种情况如何处理。

**修改建议**：

1. 明确新设备、恢复出厂、存量设备升级三种路径。
2. 增加调度配置版本或迁移标记，首次进入新固件时显式决定：迁移为 10 分钟，或保留运维配置但排除其来自 10 分钟默认验收。
3. 若选择平台下发迁移，必须定义失败重试与未迁移状态上报。
4. 将该用例加入配置测试。

### P1-4 动态覆盖率公式在 50 Hz 最大窗口会中间溢出

第 5.5 节公式为：

```text
expected_samples += segment_duration_ms * rate_hz / 1000
```

合法诊断模式包含 `50 Hz + 1440 min`：

```text
86400000 ms * 50 = 4320000000
```

该中间乘积超过 `uint32_t` 上限 `4294967296`。最终样本数约 4.32M 可以用 32 位保存，但中间乘法必须使用 64 位或有理累加。

**修改建议**：

1. 明确 `segment_duration_ms` 与 `rate_hz` 的乘法必须用 `uint64_t` 中间量。
2. 或按采样计数直接累加，不通过时间反推。
3. 测试计划加入 `50 Hz + 1440 min` 的 `expected_samples` 边界用例。

### P1-5 AOI HPF 缺少启动、复位与模式切换序列

`FDS=0 + HPIS1=1` 的稳态语义正确，但 HPF 在上电、ODR 切换、量程切换和传感器重配后会有建立过程。当前设计没有规定：

1. 重配时先屏蔽 AOI 中断。
2. 复位 HPF 参考。LIS3DH normal HPF mode 可通过读 `REFERENCE` 寄存器复位。
3. 等待至少一个 ODR 周期或丢弃首批高频样本。
4. 清除 `INT1_SRC` 锁存后再重新打开 AOI。

缺少该序列时，低功耗与高频档切换可能因滤波器建立瞬间反复触发 AOI，导致频繁升频和功耗异常。

**修改建议**：在第 4.3.3 升频/降频流程中加入“屏蔽 AOI → 重配 → 复位 HPF → 等待/丢弃样本 → 清锁存 → 恢复 AOI”的固定顺序，并增加模式切换后静止设备不误升频的测试。

## 4. 建议同步修正的 P2

1. **`ms_uptime` 挂点写错**：当前工程 1ms 中断由 TIM6 调用 `Systick_1ms_Handler()`，`SysTick_Handler()` 为空。文档应写“TIM6 1ms ISR”或明确真正启用 SysTick；代码改动清单也应同步。
2. **confirmed/unconfirmed 切换语义未展开**：告警 confirmed、周期摘要 unconfirmed 意味着模组确认模式可能需要按帧切换。需明确 AT 命令切换状态、失败回退，或定稿所有上行均 confirmed 并重新评估功耗。
3. **Flash CRC 细节未定**：`magic`、`version`、CRC 算法、初值、字节序、CRC 覆盖范围均未定义。应补齐，避免实现与测试各自假设。
4. **27B 结构与现有 word 写接口不齐**：现有 `FLASH_Write_NWord()` 按字写入，27B 结构需要显式 padding 到 28B/32B，且不得把 padding 纳入 CRC 或必须定义其初始化值。
5. **`0xB3` flags `00` 未定义**：设备启动读到损坏 Flash 后回默认但尚未持久化时，当前配置来源既不是显式 persist 也不一定是 temporary。建议定义 `00 = factory/default runtime`。
6. **ACK 错误码帧布局未定义**：第 8.6 只列数值，未定义错误码放在 ACK 数据域第几个字节、是否保留 `0xFF` 成功样式。平台联调前应补帧格式。

## 5. 建议修订顺序

1. 修正 FIFO 预算分解，并引入按采样率计算的 watermark/deadline 表。
2. 将 INT1 单脚多事件方案定为主方案，修正测试与代码改动清单。
3. 扩展 `0xB1` 事件时间字段或显式收缩验收承诺。
4. 补 10 分钟周期迁移策略。
5. 补 50 Hz `expected_samples` 中间量宽度和 HPF 复位序列。
6. 清理 P2 协议与存储细节。
7. 再按第 15.2 节执行 POC-1/POC-2。

## 6. 最终判断

V1.3.1 的主体架构和大多数评审闭环质量较高，尤其是统计、快照、异步范围、资源红线和功耗口径已经比较扎实。但在当前版本中，25 Hz 时序预算自身加错、50 Hz 诊断模式必 overrun、INT 路由方案与芯片能力不一致，这三处会直接误导实现。

建议先出 V1.3.2 做文档级修正，再进入原理图人工对图和 POC。本轮仍未编译，属于设计静态复查。
