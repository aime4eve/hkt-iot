## 2. 目标

在两次 LoRaWAN 周期上报之间持续采集加速度，并在固件内本地计算摘要统计：

1. 每个间隔的平均原始合成加速度幅值。
2. 每个间隔的最大原始合成加速度幅值。
3. 每个间隔的活动与非活动时间百分比。

同时支持异常运动峰值检测与实时性告警：

1. 事件触发后异步主动上行。
2. 网络失败时缓存并在恢复后补报。
3. 告警成功后打开短时 Class C 配置窗口。

## 2.1 客户原始需求

客户确认的原始指标需求如下：

| 编号 | 客户需求 | 业务目的 |
|---|---|---|
| CR-01 | 每个间隔的平均加速度大小，计算公式为 `sqrt(x^2 + y^2 + z^2)` | 表征统计窗口内整体运动强度 |
| CR-02 | 每个间隔的最大加速度幅度 | 检测异常运动峰值 |
| CR-03 | 每个间隔内活动时间与非活动时间百分比，基于内部移动阈值 | 主动/非活动分类 |
| CR-04 | 通过以上指标检测异常运动峰值，触发防盗/捕食者告警 | 支持防盗与捕食者风险提醒 |

客户明确三项指标为其完整且最终的功能指标清单，本项目不额外扩展原始波形上传或行为建模功能。

## 2.2 客户原始需求分析

### 2.2.1 需求可行性与技术含义

| 客户需求 | 可行性 | 技术含义 |
|---|---|---|
| CR-01 平均加速度大小 | 可行 | 必须在固件内逐采样点计算 `sqrt(x^2+y^2+z^2)` 并在线累加，上报窗口结束前不需要保存原始三轴波形。该值为原始合成幅值，静止时通常接近 `1g`，不是零基线运动量 |
| CR-02 最大加速度幅度 | 可行 | 必须在完整统计窗口内持续或高覆盖采样，否则短促冲击可能完全落在未采样时间段。传感器量程必须大于业务峰值，否则最大值会被削顶 |
| CR-03 活动/非活动百分比 | 可行 | 不能直接用三轴绝对值或原始幅值是否超过阈值判断，因为重力使静止幅值约为 `1g`，且安装方向会变化。应使用 `abs(合成幅值-1g)` 作为方向无关的动态运动强度 |
| CR-04 异常峰值告警 | 可行，但超出简单统计上报范围 | 只依赖周期上报会引入最长一个上报周期的告警延迟。要满足时效，需要加速度计中断唤醒、事件状态机、异步 LoRa 发送、失败缓存和补报 |

### 2.2.2 由原始需求推导出的约束

1. **统计窗口完整性**
   - 客户要求覆盖两次 LoRa 上报之间的完整时间段。
   - 当前固件行为（区分口径，避免误述）：入网运行态固件不进入 Stop，MCU 常醒，工作态采样 50 Hz；`control_center.c` 中的 LIS3DH power down 只发生在 `!powerState` 的关机/待机分支；未入网且空闲时才进入 Stop，休眠态没有采样。
   - 新设计目标：默认连续模式下 LIS3DH 常开，统计覆盖完整窗口；本版沿用"入网后 MCU 常醒"架构（见第 11.1 节），不引入每秒 FIFO 浅唤醒路径。

2. **峰值可信度**
   - 当前量程为 ±2g，剧烈冲击可能饱和。
   - 为避免最大幅值削顶，默认量程调整为 ±4g，并保留 ±8g 下行切换能力。
   - 采样率默认 25 Hz，可捕捉较明显的运动峰值，但不能承诺捕捉所有短促冲击。

3. **活动分类语义**
   - 平均和最大值按客户公式上报原始合成幅值。
   - 活动分类必须基于 `abs(合成幅值-1g)`，否则静止重力会被误判为活动。
   - 低功耗模式下存在未高覆盖采样时段，活动百分比必须以有效采样点为分母，并另报采样覆盖率。

4. **告警时效与功耗平衡**
   - 告警需要事件触发后主动上行，而不是等待下一个周期上报。
   - 当前 LoRa 发送流程存在阻塞等待和长失败路径，需重构为非阻塞状态机。
   - 告警频繁上行会显著增加功耗，因此需要独立告警阈值、防抖和静默期。

5. **远程运维能力**
   - 阈值、采样模式、采样率、量程、告警参数和 Class A/C 模式需要现场可调。
   - 配置默认持久化，避免重启后丢失现场调优结果。
   - 告警后的短时 Class C 窗口用于平台立即调参、关闭误报或切换更高强度观测模式。

### 2.2.3 当前固件差距

| 当前实现 | 与客户需求的差距 |
|---|---|
| 周期上报最新瞬时 X/Y/Z | 不能代表完整统计窗口，无法计算平均幅值、最大幅值和活动百分比 |
| 工作态 50 Hz 瞬时采样，休眠态（未入网空闲 Stop、关机/待机 power down）无采样 | 统计覆盖不完整，休眠期间没有有效样本 |
| FIFO 分支未默认启用 | MCU 轮询和 I2C 读取频率偏高，不利于低功耗和稳定批处理 |
| 量程 ±2g | 异常峰值可能饱和，最大幅值不可信 |
| 步数算法基于三轴动态阈值 | 未提供原始合成幅值统计，也没有活动百分比和覆盖率 |
| LoRa 发送为阻塞式流程 | 事件告警时可能阻塞主循环，网络异常路径过长 |
| Stop 后清入网状态、模组睡眠（仅未入网空闲路径；入网态本不进 Stop） | 若未来引入入网后 Stop，事件唤醒会触发重新入网，不满足告警时效；第一版 MCU 常醒架构不涉及，会话保持依赖 POC-1 |
| 配置项不足 | 缺少采样模式、阈值、告警参数、量程和 Class C 窗口等远程配置 |

### 2.2.4 分析结论

客户的三项统计指标在固件内均可实现，核心风险不在计算复杂度，而在统计覆盖、传感器量程、告警上行路径、低功耗策略和配置持久化。最终方案采用本地在线统计加轻量摘要上报，配合独立异常事件告警，可以在不保存完整原始波形的情况下满足客户使用场景。

### V1.2（2026-08-20 首轮评审）

| 评审意见 | 结论 | 修正内容 |
|---|---|---|
| 高速率采集下需要注意功耗 | 采纳 | 默认仍为 25 Hz；50 Hz 仅允许平台显式临时开启用于诊断或追踪，不作为持久化长期配置，也不纳入默认电池寿命验收 |

## 4. 已确认需求

### 4.1 统计窗口

- 统计窗口覆盖两次 LoRaWAN 周期上报之间的完整时间段。
- 默认周期为 10 分钟 GPS 定位 + LoRa 上报。
- 上报窗口结束时输出统计，并清空下一窗口累加器。
- 统计只基于有效采样点；未采样时间不推断为活动或非活动。
- 每个窗口同时上报有效采样覆盖率，用于平台判断统计可信度。

### 4.2 加速度指标

原始合成加速度幅值定义为：

```text
magnitude = sqrt(x^2 + y^2 + z^2)
```

**传感器前置条件（强制）**：统计路径必须关闭 LIS3DH 高通滤波的**数据通路**，使用未滤波的原始 X/Y/Z 输出。当前 `acc.c` 活动路径启用了 `lis3dh_config_hpf(..., data=true, ...)`（`USER/Drive/acc.c:375`），若继续开启数据通路 HPF，静止合成幅值趋近 0 而不是 1g，`abs(magnitude - 1g)` 的活动分类与告警判定全部失效。统计模式初始化时必须显式配置 `FDS=0`；注意"关闭"仅指数据通路——AOI 中断判定通路反而必须开启 HPF（`HPIS1=1`），两者相互独立，见第 4.3.3 节。现有步数等其他功能如需 HPF，必须在模式切换时一并切换，禁止共用冲突配置。

**量化精度说明**：LIS3DH 高分辨率 12 位输出下，±2g 量程 LSB 约 0.98 mg，±4g 约 1.95 mg，±8g 约 3.9 mg。协议以整数 mg 上报，但不得向平台承诺 1 mg 绝对精度；平台展示精度按当前量程的 LSB 取整。

上报值使用原始合成幅值，不扣除重力基线：

| 指标 | 定义 | 单位 |
|---|---|---|
| 平均幅值 | `sum(magnitude) / valid_samples` | mg |
| 最大幅值 | `max(magnitude)` | mg |
| 活动百分比 | `active_samples * 100 / valid_samples` | `%` |
| 非活动百分比 | `100 - activity_percent` | `%` |
| 采样覆盖率 | `valid_samples * 100 / expected_samples` | `%` |

活动样本判定使用动态运动强度：

```text
dynamic_magnitude = abs(magnitude - 1g)
active = dynamic_magnitude >= activity_threshold
```

默认活动阈值为 `250 mg`。

**幅值语义提示（平台必读）**：`0xB0` 摘要与 `0xB1` 告警峰值上报的都是**原始合成幅值**（含重力，静止约 1000 mg）；活动百分比与告警判定使用的是**动态幅值** `abs(magnitude - 1g)`。两套量纲不可直接比较：平台不得把 `1750 mg` 的原始峰值解释为"超过 750 mg 告警阈值"，等价的动态幅值是 `750 mg`。平台界面与告警文案必须区分这两个量纲。

### 4.3 采样模式

配置结构使用两个独立的采样率字段，不得复用单一 `sampling_rate_hz`：

- `low_power_sampling_rate_hz`：低功耗模式的稀疏采样率，默认 `1 Hz`。
- `active_sampling_rate_hz`：连续模式的采样率，以及低功耗模式运动后升频的目标采样率，默认 `25 Hz`。

连续模式只使用 `active_sampling_rate_hz`；低功耗模式在两者之间切换。两个字段独立下行配置，独立校验，独立持久化。

#### 4.3.1 连续统计模式（默认模式）

- LIS3DH 常开。
- 采样率取 `active_sampling_rate_hz`，默认 `25 Hz`。
- 启用 FIFO 批读，降低 MCU 与 I2C 唤醒频率。
- 默认量程 `±4g`，高分辨率模式。
- `active_sampling_rate_hz` 可通过下行修改。
- 连续模式默认不自动回退。
- 连续模式最大持续时间保护支持配置，默认关闭。

**50 Hz 临时诊断模式边界**：`50 Hz` 仅允许作为平台显式开启的临时诊断/追踪采样率：

1. 只能以临时生效方式下发（`0xB2` flags 非 persist）；持久化配置请求包含 `50 Hz` 时返回参数范围错误。
2. 最长持续时间默认 `30 min`（可配，范围 `1~1440 min`），到期自动恢复持久化采样率并上报一次配置。
3. 退出条件：超时、平台下发新采样率、设备重启，三者任一即退出。
4. 重启后一律恢复持久化采样率，不延续诊断模式。
5. 诊断模式期间的平均电流不计入电池寿命验收口径。

#### 4.3.2 低功耗模式

- LIS3DH 常开。
- 稀疏采样率取 `low_power_sampling_rate_hz`，默认 `1 Hz`。
- 同时启用 LIS3DH 硬件运动唤醒中断（AOI，见下）。
- 硬件运动事件触发后提升到 `active_sampling_rate_hz`（默认 `25 Hz`）。
- 持续有运动则保持高频。
- 连续 `60 s` 无运动后降回 `low_power_sampling_rate_hz`。
- 该 `60 s` 参数可通过下行修改，建议范围 `10~300 s`。

**稀疏采样语义**：`1 Hz` 稀疏采样仅用于活动趋势统计和硬件唤醒触发，不承诺捕捉短促冲击；短促事件的捕捉依赖硬件唤醒后的高频采样。低功耗模式的窗口覆盖率与告警时效承诺低于连续模式。

#### 4.3.3 硬件运动唤醒链路（定稿）

硬件事件的职责边界：**硬件 AOI 中断只用于唤醒 MCU 并切换到高频采样，不产生正式告警**。正式告警必须在高频连续采样建立后，由软件按告警阈值和持续时间防抖确认（见第 4.4 节）。

LIS3DH 中断配置：

| 配置项 | 取值 | 说明 |
|---|---|---|
| AOI 组合逻辑 | X/Y/Z 六事件 OR（每轴"高于 +阈值"与"低于 -阈值"） | 方向无关地捕捉任一轴突变 |
| AOI 阈值 | 由告警阈值推导，不可独立配置 | `hw_wake_threshold_mg = alarm_threshold_mg / 2`，下限 `125 mg`，上限 `1000 mg`；比软件告警阈值更灵敏，保证唤醒后软件有机会复判 |
| AOI 阈值量化 | 按 `INT1_THS` 7 bit 量化 | ±2g 下 1 LSB = `16 mg`，±4g 下 = `32 mg`，±8g 下 = `64 mg`；默认 `375 mg` 在 ±4g 下实际生效 `384 mg`（12 LSB）。量化误差在唤醒筛选用途下可接受，实现按目标值四舍五入取整 |
| AOI 判定数据源 | HPF 滤波后数据（CTRL2 `HPIS1 = 1`） | **中断判定通路必须开 HPF**：重力被滤除后，`hw_wake` 阈值才是动态加速度语义，与软件告警阈值同量纲。若误用原始数据，静止时任一轴重力分量 ≥ `1000/√3 ≈ 577 mg > 375 mg`，六事件 OR 恒成立，INT1 永久锁存，低功耗模式失效 |
| 统计数据源 | 原始数据（CTRL2 `FDS = 0`） | `FDS` 与 `HPIS1` 是 CTRL_REG2 中相互独立的开关；`FDS=0` 保证输出/FIFO 为未滤波数据，满足第 4.2 节统计前提。驱动 `lis3dh_config_hpf()`（`lis3dh.c:886-908`）的 `data`/`int1` 参数一一对应 |
| AOI 持续时间 | `duration = 1` 个 ODR 周期 | 最灵敏档；稀疏 ODR 下即单样本越限触发 |
| HPF 截止档（HPCF） | 最低截止档 | 缓慢姿态变化（如安装面缓慢倾斜）被滤除不触发；截止频率随 ODR 变化，以数据手册为准 |
| 锁存 | 使能锁存（LIR_I1） | 唤醒后读 `INT1_SRC` 清除并识别中断源 |

各模式 FIFO watermark 配置（deadline 公式与预算见第 5.4 节）：

| 模式 | ODR | watermark | 批读节奏 |
|---|---:|---:|---|
| 连续 25 Hz | 25 Hz | 25 级 | 约 1 s 一批，理论上限 280 ms |
| 连续 50 Hz（临时诊断） | 50 Hz | **12 级** | 约 0.24 s 一批，理论上限 400 ms；不得沿用 25 级（余量仅 140 ms） |
| 连续 10 Hz | 10 Hz | 25 级 | 约 2.5 s 一批，理论上限 700 ms |
| 低功耗稀疏 | 1 Hz | 10 级 | 约 10 s 一批，余量 22 s |
| 低功耗稀疏 | 10 Hz | 10 级 | 约 1 s 一批，理论上限 2.2 s |
| 升频后 | `active_sampling_rate_hz` | 按目标档位查本表 | 切换时同步更新 |

关键点：低功耗模式下运动升频由 AOI 事件即时触发，**不等待 FIFO watermark**，因此稀疏 watermark 取 10 级不会延迟升频时效；但稀疏 watermark 不得沿用 25 级（1 Hz 下 MCU 约 25 s 才处理一次，会延迟统计并造成旧样本积压）。

INT 路由与中断源识别（定稿，与 LIS3DH 能力对齐）：

- **主方案（单 INT1 多事件）**：通过 CTRL_REG3 同时开启 `I1_IA1` 与 `I1_WTM`，AOI 与 FIFO watermark 同路由到 INT1；唤醒后软件读 `INT1_SRC`（AOI 源）与 `FIFO_SRC`（watermark/overrun 状态）区分事件类型。选择依据：LIS3DH 的 FIFO watermark 只能路由到 INT1（`lis3dh_types.h` 标注 `only INT1`），无法放到 INT2；单脚方案与当前固件仅 PB7 一路 ACC EXTI（`gpio.c:100-115`）的现状一致，无需硬件改动。
- **可选增强（需原理图确认）**：若人工对图确认 INT2 已接入 MCU，可反向分脚提升区分度：INT1 = FIFO watermark（`I1_WTM`），INT2 = AOI1（经 `CTRL6.I2_AOI1` 路由）。注意方向不可颠倒（watermark 不能去 INT2）。
- **硬件验证待办**：原理图 `Docs/LL_V02原理图_0205.pdf` 文本提取显示 INT2 网络仅紧邻测试点 TP10，POC-2 启动前人工对图确认，据此决定是否启用可选增强。
- 无论哪个方案，唤醒后软件都必须读寄存器确认真实中断源，不得只凭引脚电平判断。

升频与降频切换流程（含 HPF/AOI 复位序列，定稿）：

```text
1. AOI 触发 → 读 INT1_SRC 清锁存 → 立即结算当前稀疏段 expected_samples（见 5.5 节）
2. 屏蔽 AOI 中断（避免重配与滤波器建立期间误触发）
3. 清 FIFO，按 active_sampling_rate_hz 重配 ODR 与 watermark（按上表），读回验证
4. 复位 HPF：读 REFERENCE 寄存器（normal 模式复位滤波器参考）
5. 等待并丢弃滤波器建立期样本（建立期数据不进入统计与判定）；丢弃窗口按 ODR 缩放——HPF 截止频率正比 ODR，1 Hz 档建立时间约为 25 Hz 档的 25 倍，"1 个 ODR 周期"下限从宽，具体窗口以 POC-2 实测为准
6. 读 INT1_SRC 清除重配期间可能置位的锁存
7. 恢复 AOI 中断，防抖计时从首个有效高频样本重新开始，不继承稀疏期状态
```

降频流程对称执行（步骤 1 结算高频段，其余同 2~7，重配为稀疏档）。缺少步骤 2/4/5/6 时，滤波器建立瞬间可能反复触发 AOI，导致频繁误升频和功耗异常——该序列为强制顺序，不得省略。

### 4.4 异常运动告警

告警与活动分类使用不同阈值：

| 参数 | 默认值 | 说明 |
|---|---:|---|
| 告警开关 | 开启 | 可下行开关 |
| 告警阈值 | `750 mg` | 基于动态运动强度 |
| 防抖持续时间 | `120 ms` | 连续满足阈值才触发 |
| 静默期 | `10 min` | 静默期内不重复上行 |

告警判定公式：

```text
dynamic_magnitude >= alarm_threshold
```

必须在 `alarm_debounce_duration_ms` 时间内持续满足阈值条件才产生事件。防抖按持续时间而非固定采样点数定义，避免同一配置在 1 Hz、25 Hz、50 Hz 下语义差异过大。实现时按当前采样率换算所需采样点数；`25 Hz` 下默认约对应连续 3 个采样点。静默期内继续更新平均值、最大值和活动统计，但不重复发送告警。

**告警判定只在高频采样期进行**：`alarm_debounce_duration_ms` 默认 `120 ms`，在 `1 Hz` 稀疏采样下退化为单点判定，无法验证持续时间语义。因此定稿规则为：

1. 软件告警判定（阈值 + 持续时间防抖）只在 ODR ≥ `10 Hz` 的采样段执行。
2. 稀疏采样段（1 Hz）不产生正式告警判定，只更新统计累加器；可能的告警由 AOI 硬件事件触发升频后，在高频段由软件复判确认。
3. 防抖计数在升频后重新开始，稀疏期样本不参与防抖计数。
4. 若 AOI 唤醒后高频段未确认告警，事件不产生，仅计入统计。

### 4.5 告警上行时效

验收承诺：

- 典型 `1 min` 内完成告警上行。
- `5 min` 内高概率完成。
- 网络失败时缓存事件，恢复后补报。

**发送成功判据（定稿）**：**所有上行统一使用 confirmed uplink**（模组 `AT+CONFIRM` 保持确认模式，不按帧切换）。模组报告发送完成且未要求重传，即视为一次成功；MAC 层确认由模组在 RX1/RX2 窗口内处理。统一 confirmed 的依据：Class A 上行后 RX1/RX2 接收窗口本来就会开启，确认帧的边际功耗仅在网关丢包触发重传时产生，而重传正是补报语义所需；同时避免模组确认模式按帧来回切换的 AT 交互开销与失败回退路径。平台应用层 ACK 不作为成功判据（Class A 下行窗口时序无法保证），但可作为可选增强在常驻 Class C 运维模式下启用。周期摘要失败仍按快照缓存补发处理。

**告警重试与网络恢复（定稿）**：

1. 告警事件有独立重试退避：首次失败后 `60 s` 重试，指数退避至上限 `10 min`。
2. 告警路径**豁免**现有"连续失败后 30 分钟重连退避"：告警重试只受自身退避约束，不叠加 30 分钟退避；只有模组明确报告未入网（`joinState` 丢失或模组状态查询确认掉网）时，告警发送才转入重连流程。
3. 补报触发点（三触发合一，任一满足即尝试）：
   - 后续任意上行成功后（含周期摘要、配置 ACK 上行）。
   - 告警自身退避定时到期。
   - 周期上行时刻顺带检查事件缓存。
4. 事件缓存深度 8 条（RAM 约 80 B，第 11.4 节红线内）；缓存满时丢弃最旧事件并累加丢弃计数。按静默期 10 min 计，8 条可覆盖约 80 min 断网期间的告警积压。
5. 被丢弃事件通过 `0xB1` 的 `dropped` 字段上报（见第 8.2 节），平台可感知补报不完整。

告警发送必须采用异步非阻塞状态机，不能阻塞 ACC 采样和主循环。

### 4.6 LoRaWAN Class A/C 规则

- 默认 Class A，电池优先。
- 支持通过下行切换为常驻 Class C。
- 告警上行成功后自动打开 Class C 配置窗口：
  - 默认时长 `5 min`。
  - 窗口结束后自动回到 Class A。
  - 窗口时长可通过下行修改。
- Class A 常态下，平台下行必须排队到设备下一次上行后的 RX1/RX2 窗口。
- 常驻 Class C 定义为运维/应急模式，不作为默认运行模式。

## 5. 总体架构

```text
LIS3DH FIFO / sample
        |
        v
ACC statistic accumulator
    |- magnitude sum
    |- magnitude max
    |- active sample count
    |- valid sample count
    |
    |-- periodic report -> ACC summary TLV
    |
    +--> alarm detector
              |
              v
        alarm event queue
              |
              v
        async LoRa sender
              |
              +--> alarm uplink
              +--> failure cache and retry
              +--> temporary Class C window
```

### 5.1 统计累加器

建议使用整数或定点计算，避免长时间浮点累计误差。

```c
typedef struct {
    uint64_t magnitude_sum_mg;   /* 64 位累加，覆盖协议最大窗口，见下文容量证明 */
    uint16_t magnitude_max_mg;
    uint32_t valid_samples;
    uint32_t active_samples;
    uint32_t expected_samples;   /* 分段结算累加，见 5.5 节 */
} acc_stats_t;
```

`magnitude_sum_mg` 必须使用 64 位累加器（RAM 增量仅 4 B，除法每窗口只执行一次）：

- 默认 `25 Hz + 10 min` 窗口：三轴同时饱和的合成幅值上限约 `13856 mg`，累加上限约 `2.08e8`，`uint32_t` 足够。
- 协议允许的最大窗口 `25 Hz + 1440 min`：按单轴满量程 `8000 mg` 累加约 `1.73e10`，按三轴合成上限 `13856 mg` 累加约 `3.0e10`，均超出 `uint32_t` 上限 `4.295e9`。
- 结论：32 位累加器无法覆盖协议允许的最大窗口，必须使用 64 位；`uint64` 上限 `1.8e19`，对所有合法"采样率 × 量程 × 窗口"组合均有充足余量，无需限制配置组合。
- 平均值计算使用 64 位被除数、32 位除数的除法（Cortex-M0+ 软件除法，每窗口一次，可接受）；不得在逐样本路径做 64 位除法。

每个有效采样点执行一次更新：

1. 计算 `magnitude_mg`。
2. 累加到 `magnitude_sum_mg`。
3. 更新 `magnitude_max_mg`。
4. 计算 `dynamic_magnitude_mg = abs(magnitude_mg - 1000)`。
5. 若 `dynamic_magnitude_mg >= activity_threshold_mg`，增加活动样本计数。
6. 增加有效样本计数。

平均幅值计算：

```text
average_mg = (magnitude_sum_mg + valid_samples / 2) / valid_samples
```

覆盖率计算：

```text
coverage_percent = valid_samples * 100 / expected_samples
```

若 `valid_samples == 0`，上报无有效采样错误码，不得除零。

### 5.2 FIFO 采样

- **FIFO 模式定稿为 stream 模式**：连续统计需要持续保留最新样本，stream 模式 overrun 后新样本覆盖最旧样本，语义为"始终保留最新 32 级"。不使用 collect 模式（collect 在 overrun 后停止收集，需重建）。
- **stream 模式 overrun 语义**：FIFO 满后新样本持续写入并逐个覆盖最旧样本，任意时刻 FIFO 内始终保留**最近的 32 个**有效样本。因此 overrun 前后不存在新旧样本交织问题——批读得到的是读取时刻最近 32 个真实样本，时间缺口体现在样本数与 `expected_samples` 的差值中。处理规则：
  1. 批读前检查 `FIFO_SRC` 的 `OVRN` 位；置位时先记录 overrun 事件（置窗口 overrun 标志、扣减覆盖率），清 FIFO 重建采样状态，本批样本仍计入统计（它们是真实样本，只是有时间缺口）。
  2. 缺失样本数不推断、不补造，仅通过 `expected_samples - valid_samples` 反映在覆盖率中。
- watermark 配置见第 4.3.3 节：连续 25 Hz 用 25 级，稀疏 1 Hz 用 10 级。
- **批量读定稿为一次 I2C 事务**：使用寄存器地址自动递增（`OUT_X_L` 起始，`IF_ADDINC` 开启），按 `FIFO_SRC.FSS` 级数一次读 `num * 6` 字节到原始样本缓冲。当前驱动 `lis3dh_get_raw_data_fifo()` 为逐样本 6 字节多次读取，必须先改造为批量读（见第 12 节驱动修复项），否则 I2C 事务次数和占用时间放大 25 倍。
- 读取失败时保留已读样本，记录采样缺口。
- 运行架构口径（第一版）：入网后 MCU 常醒，不存在"Stop 前关 LIS3DH"路径；power down 仅允许出现在关机/待机分支（与现状一致）。低功耗模式为传感器 1 Hz + MCU 常醒降载，不是 MCU Stop。Stop + FIFO 浅唤醒架构为后续优化项，见第 11.1 节。

### 5.3 统计快照与发送并发

LoRa 发送、告警处理和 ACC 采样并发运行时，周期统计不得直接引用正在变化中的累加器。窗口到期或事件触发时采用快照机制：

```text
current accumulator -> copy to immutable snapshot -> reset accumulator
                                          |
                                          v
                              periodic summary / alarm frame
```

要求：

1. 快照复制和累加器重置必须在同一个临界区内完成，或由单一采样任务串行执行，避免窗口边界重复或漏计。
2. 快照一旦生成即不可修改，LoRa 发送失败只能影响该快照的上行，不得影响下一窗口统计。
3. 周期摘要快照发送失败时进入待补发缓存；缓存不足时丢弃最旧摘要并记录计数，不得覆盖告警事件。
4. ACC FIFO 读取和统计更新优先于 LoRa 状态机轮询，防止发送流程造成 FIFO overrun。
5. FIFO 已 overrun 时，本窗口覆盖率下降并置 overrun 标志；缺失时间不得推断为活动或非活动。

### 5.4 低速 MCU 下的 25 Hz 批处理策略

评审指出 MCU 在低速时钟下运行，低功耗模式运动后 25 Hz 批处理能力必须验证。本设计先不默认提高系统主时钟，而按以下方式降低处理压力：

1. **一次批量读取 FIFO**
   - 25 Hz 高频保持期不是逐点读传感器。
   - FIFO watermark 触发后一次读取整批样本。
   - 每秒约 25 个采样点、每点 3 轴，共约 150 B 原始数据。
   - I2C 使用寄存器地址自动递增，一次传输读取整批数据。

2. **使用整数开方，不引入 CMSIS-DSP**
   - 不使用浮点 `sqrt()` 作为实时路径的默认实现。
   - 也不默认引入 `arm_sqrt_q15` 等 CMSIS-DSP 定点函数：其依赖库体积在当前 ROM 余量（约 10 KB）下未验证，且需要 q15 定标转换。
   - 合成幅值使用小型整数开方（逐位逼近或牛顿迭代 `isqrt32`，代码量数十字节）。输入域证明：±8g 量程下单轴 `8000 mg`，平方和最大 `3 * 8000^2 = 1.92e8 < 2^31`，32 位运算即可承载，`isqrt32(1.92e8) = 13856`。
   - 阈值比较和累加器均使用整数运算。
   - 原始 FIFO 缓冲使用静态 `int16_t` 数组（25 级 × 3 轴 × 2 B = 150 B），不使用 float 数组或动态分配。

3. **FIFO 处理时限体系（定稿，按采样率计算）**
   - FIFO 深度 32 级。watermark 触发后的 FIFO 充满时间即理论硬上限：

     ```text
     deadline = (32 - watermark) / rate
     ```

   - 各采样率档位的 watermark 与时限（watermark 中断路由见第 4.3.3 节）：

     | 采样率 | watermark | 触发后余级 | 理论上限 deadline | 实测红线 | 批次间隔 |
     |---:|---:|---:|---:|---:|---:|
     | 25 Hz（连续默认） | 25 | 7 级 | 280 ms | **< 250 ms** | 1.0 s |
     | 50 Hz（临时诊断） | 12 | 20 级 | 400 ms | **< 250 ms** | 0.24 s |
     | 10 Hz | 25 | 7 级 | 700 ms | < 500 ms | 2.5 s |

     50 Hz 不得沿用 watermark 25（触发后仅 140 ms，任何实现必 overrun），强制使用 watermark 12。
   - **中断到批处理完成的预算分解（严格求和，25 Hz 与 50 Hz 统一）**：

     ```text
     任务步进占用 ≤ 50 ms
     + EXTI 置位后批处理等待 ≤ 100 ms
     + 批处理本身 < 100 ms
     = 合计 ≤ 250 ms，对 25 Hz 理论上限 280 ms 保留 30 ms 余量（采样抖动、中断响应、测量误差）
     ```

     该分解为最坏预算：I2C 失败重试、Flash 步进、GPS 解析等任务并发时按各自最坏占用计入"任务步进占用"，不得只按名义耗时。
   - 备用纯轮询配置（仅当 POC 证明 EXTI 不可用时启用）：watermark 降为 12 级，轮询周期 ≤ `500 ms`；25 Hz 下触发后余 20 级即 800 ms，扣除轮询周期后仍有 300 ms 余量。轮询模式同样必须满足 `轮询周期 < (32 - watermark) / rate`。
   - 异步 LoRa、GPS、日志等任何任务的单次最长占用必须小于 50 ms（25 Hz 预算分解的上限），否则视为阻塞违例（与第 7 章异步化要求一致）。

4. **执行时间压测**
   - 使用 GPIO 翻转或 SysTick 测量单批处理耗时。
   - 分别记录 I2C 读取时间、统计计算时间、单批总处理时间和主循环最大延迟。
   - 在低速时钟、25 Hz、LoRa 异步发送激活、GPS/RTC 处理同时存在的工况下压测。
   - 连续运行至少 60 s 高频保持窗口，不允许 FIFO overrun。

5. **优化路径**
   - 若低速时钟余量不足，优先降低批处理调度延迟和避免非必要任务。
   - 其次将批量读取改为 I2C 中断或 DMA。
   - 再次仅在 FIFO 批处理期间短时提高 MSI/PLL 主频，处理完成后恢复原时钟或重新进入低功耗。
   - 不默认长期提高主时钟；任何升频都必须通过平均电流实测验证。

6. **验收标准**
   - 单批 ACC 处理时间小于 100 ms。
   - 25 Hz（watermark 25）与 50 Hz（watermark 12）下，中断到批处理完成实测均 < 250 ms；各自理论上限（280/400 ms）不得触碰。
   - 高频保持窗口内 FIFO overrun 为 0（25 Hz 连续 60 s；50 Hz 诊断模式连续 30 min，见第 13.2 节）。
   - 实时路径不出现浮点格式化日志（`printf`/`sprintf` 带 `%f`），调试输出使用整数格式。
   - 若采用升频，升频窗口内的增量电荷和平均电流必须有实测数据。

### 5.5 时间服务与动态覆盖率

**毫秒计时跨零问题**：当前 `get_syspant_ms()`（`USER/Drive/systick.c:293`）在 `sys_pant_ms > 86400000` 后清零——它是**模 86400000** 的计数器，不是模 2^32 自由回绕。防抖计时、静默期、窗口到期、发送超时若直接比较时间戳（如 `deadline > now` 写法，现存于 `control_center.c:86` 等），会在清零点瞬间误判；且无符号减法 `now - start` 的回绕安全性**只对模 2^32 自由回绕计数器成立**，对模 86400000 计数器同样误判（例：`start = 86399990, now = 5`，`now - start` 按模 2^32 得约 `4.29e9` 而非真实流逝的 `15 ms`）。

定稿要求：

1. **新增自由运行毫秒计数 `ms_uptime`（`uint32_t`，在 TIM6 1 ms ISR 即 `Systick_1ms_Handler()`（`USER/Drive/tim.c:17-22`）中自增、永不清零）**，自然模 2^32 回绕，约 49.7 天回绕一次。注意当前工程 `SysTick_Handler()` 为空、真正的 1 ms 节拍来自 TIM6，挂点不得写错。`get_syspant_ms()` 及其 86400000 清零行为保持不动（存量代码依赖），所有新增计时逻辑一律以 `ms_uptime` 为时基。

2. 新增回绕安全的时间差函数（时基为 `ms_uptime`），所有新增计时逻辑必须使用，禁止直接比较两个毫秒时间戳：

   ```c
   /* 回绕安全：返回 now 距 start 已流逝的毫秒数。
      前提：时基必须为模 2^32 自由回绕计数器（ms_uptime），
      且 duration < 2^31，保证差值无歧义。 */
   uint32_t ms_elapsed(uint32_t start_ms, uint32_t now_ms)
   {
       return now_ms - start_ms;   /* 无符号减法，模 2^32 语义 */
   }
   ```

   到期判断统一写为 `ms_elapsed(start, now) >= duration`，不得写为 `now >= deadline`，也不得把 `get_syspant_ms()` 的返回值传给 `ms_elapsed`。

3. 存量代码中同模式的直接比较（`LoRaWAN_APPLY.c:439`、`gps.c:428`、`acc.c:280` 等）在本次改造触及相关文件时迁移到 `ms_uptime + ms_elapsed`；不强制一次性全量重写。

4. 事件缓存记录事件发生时刻的毫秒计数 `event_ms`（`ms_uptime` 时基），补报时用 `ms_elapsed(event_ms, now)` 换算延迟分钟数（见第 8.2 节）；若换算结果超出 `0xB1` 字段量程（254 min），上报时间未知（`0xFF`）。

**动态覆盖率的分段累加**：低功耗模式在 1 Hz 与 25 Hz 间切换时，`expected_samples` 必须按每段实际时长和该段 ODR 分段结算累加，不得在窗口结束时用"当前采样率 × 窗口时长"反推：

```text
expected_samples += (uint64_t)段时长_ms * 段采样率_hz / 1000   （每次采样率切换时、窗口到期时结算）
```

**乘法宽度强制 64 位**：50 Hz 诊断模式下 `86400000 ms * 50 = 4.32e9`，已超 `uint32_t` 上限 `4.295e9`——中间乘积必须使用 `uint64_t`，仅最终结果（约 4.32e6 样本）截断回 32 位累加。逐段结算时段时长远小于整窗口，实际中间值很小，但类型必须按最坏情形声明。

切换点结算由第 4.3.3 节升频/降频流程在第 1 步强制执行；窗口到期快照时先结算当前段再生成快照。

## 6. 告警状态机

```text
IDLE
  |-- threshold passed --------> DEBOUNCE
  |-- threshold not passed ----> IDLE

DEBOUNCE
  |-- consecutive N points ----> ALARM_PENDING
  |-- one point below ---------> IDLE

ALARM_PENDING
  |-- LoRa idle and joined ----> SENDING
  |-- busy --------------------> ALARM_PENDING

SENDING
  |-- success -----------------> SENT, start quiet period, open Class C window
  |-- fail --------------------> CACHED

CACHED
  |-- network recovered -------> SENDING
  |-- newer alarm -------------> keep peak/event metadata only
```

要求：

1. 防抖状态保存起始时间和持续时间；采样率切换时按剩余持续时间重建计数，不使用固定采样点数跨采样率比较。
2. 事件缓存保留事件序号、触发时刻毫秒计数 `event_ms`、峰值和丢弃计数，深度 8 条（见第 4.5 节）；补报时按第 5.5 节回绕安全时间差换算延迟分钟数。
3. 静默期内新事件只更新统计和峰值，不重复入队。
4. 补报事件需标记为延迟事件并携带延迟分钟数（第 8.2 节），避免平台误认为刚发生。
5. 告警重试退避、补报触发点和豁免 30 分钟重连退避的规则见第 4.5 节。

## 7. LoRa 发送改造

当前 `sendLoRaWANData()`（位于 `USER/Drive/communicate.c`，非 `Compents/LoRa/LoRaWAN_APPLY.c`）具备唤醒模组、切换透传模式和发送能力，但存在阻塞等待和失败路径过长的问题。本设计要求改造为异步状态机。

**职责划分（定稿）**：上行数据路径（周期摘要、告警、ACK 上行）的异步状态机改造在 `USER/Drive/communicate.c` 内实现（`sendLoRaWANData` 所在层）；模组命令层拆两个文件——AT 命令原语（`AT_Exec_SendCMD`、`AT_LoRaWAN_setClass()`、`AT_LoRaWAN_getClass()` 等，位于 `Compents/LoRa/LoRaWAN_ATCMD.c`）的超时与重试非阻塞化在原文件实现；应用流程层（入网管理、模组睡眠/唤醒、初始化序列）在 `Compents/LoRa/LoRaWAN_APPLY.c` 实现。三层都不得含无限等待循环。

**异步化范围（定稿，缺一不可）**：以下全部路径纳入统一的异步状态机管理，任何一条阻塞都会在 25 Hz 下造成 FIFO overrun（250 ms 实测红线 / 280 ms 理论上限，见第 5.4 节）：

1. 周期上行 `sendLoRaWANData()` 的 Busy 无超时死等（`communicate.c:210`）。
2. 平台 ACK 上行路径（`communicate.c:331`，同一模式的第二处死等）。
3. 告警成功后的 `AT_LoRaWAN_setClass()`（`LoRaWAN_ATCMD.c:1069`）：3 次重试 ×（1.5 s 命令超时 + 1 s 延时）最坏阻塞约 7.5 s，必须拆为非阻塞子状态（发 AT 命令 → 轮询模组回包带超时 → 确认 Class 生效）。
4. Class 读回与确认（`AT_LoRaWAN_getClass()` 同为阻塞重试结构）。
5. 告警后 Class C 窗口计时与到期恢复 Class A。
6. I2C 寄存器读写（两层都要改）：
   - 总线层 `USER/Drive/iic.c`：`I2C1_MasterRead/Write` 内四处裸 `while` 等标志（`iic.c:140-164`）必须加超时（建议 50 ms 量级）；`i2c_slave_read/write()` 当前恒返 0、吞掉全部错误，必须改为传播真实成败——否则上层一切失败检测形同虚设。
   - 驱动层 `Compents/Modules/lis3dh/lis3dh.c`：`lis3dh_i2c_read/write` 以底层返回值判错，底层修复后错误才能贯通到配置回滚与读回验证。
   - 连续失败达到阈值时置传感器故障标志、暂停采样任务并上报错误码，不得卡死。
7. **I2C 速率定稿目标 400 kHz**（STM32L0 与 LIS3DH 均支持）：150 B 批读约 4 ms（100 kHz 下约 15 ms，占批处理预算 15%）；POC-2 实测上拉与走线信号完整性后锁定，若必须降回 100 kHz 则批处理预算按实测重算。

### 7.1 状态与超时数值

```text
SEND_IDLE
SEND_WAKE_MODULE
SEND_WAIT_READY
SEND_UART_TRANSFER
SEND_WAIT_BUSY
SEND_WAIT_STATUS
SEND_CLASS_C_OPEN        /* 发 AT+CLASS=C，非阻塞等回包 */
SEND_CLASS_C_WINDOW      /* 窗口计时，到期发 AT+CLASS=A */
SEND_FAIL_CACHE
```

各状态超时初值（均为"模组已唤醒"前提下的单次上限，超时进入失败路径释放状态机；初值可在联调期微调，但不得取消）：

| 状态 | 超时初值 | 依据 |
|---|---:|---|
| SEND_WAKE_MODULE / SEND_WAIT_READY | 5 s | 模组唤醒与 Busy 就绪 |
| SEND_WAIT_BUSY（等 Busy 拉低） | 5 s | 取代 `communicate.c:210` 死等 |
| SEND_WAIT_STATUS（等发送结果，含 confirmed 重传） | 30 s | 现状 `AT_LoRaWAN_setConfirm(1, 3)`（`LoRaWAN_APPLY.c:340`）3 次重传，按最大重传间隔加 RX 窗口余量 |
| SEND_CLASS_C_OPEN（单次 AT 命令） | 5 s | 取代 `AT_LoRaWAN_setClass` 单次 1.5 s 超时，重试由状态机间退避承担，不再同步 `mDelay(1000)` |
| SEND_CLASS_C_WINDOW | 窗口时长（默认 5 min） | 计时到期，非超时 |

状态机整体占锁上限 = 各状态超时之和的上界约 45 s；周期摘要与后续告警在此期间排队（快照不可变，不丢统计），与第 7.3 节优先级规则一致。所有超时判断统一走第 5.5 节回绕安全时间差。

### 7.2 必改点

1. 等待 Busy 的循环必须增加超时，不得无限等待。
2. 状态判断拆分为非阻塞超时。
3. 告警发送不得清空周期统计窗口。
4. 告警发送成功（confirmed uplink 判据，见第 4.5 节）后才启动临时 Class C 窗口。
5. Stop 前保存 LoRa 会话状态，事件唤醒后不得默认重新入网；只有模组明确失去会话时才触发重连。注意当前代码在 Stop 相关路径会清除 `joinState`，该行为必须移除；会话保持能力依赖第 15.2 节模组会话 POC 的结论，POC 未通过前不得进入实现。
6. LoRa 发送失败遵循现有缓存思路，但告警事件需要有独立重试和补报语义（第 4.5 节）。

### 7.3 发送优先级

同一时刻只允许一个 LoRa 发送流程运行，优先级如下：

```text
告警事件 > 平台触发 ACK > 周期摘要 > 配置上报
```

规则：

1. 告警事件优先于周期摘要，避免异常事件被周期发送状态延迟。
2. 周期摘要到达发送点但告警正在发送时，先生成不可变快照并排队，等待告警流程完成或超时后再发送。
3. 任何发送流程都不得暂停 ACC FIFO 读取和统计更新。
4. 发送超时后必须释放 LoRa 状态机并进入失败缓存路径，不得长期占用后续告警。
5. 告警成功后打开临时 Class C 窗口；周期摘要和配置上报成功不触发该窗口。

## 8. 协议设计

应用层仍沿用现有帧头：

```text
68 6B 74 | special_type | pack_no | payload...
```

数据编码采用大端序。

### 8.1 周期上报 ACC 摘要

新增类型 `0xB0`：

```text
Type: 0xB0
Average magnitude: uint16, mg
Max magnitude:     uint16, mg
Activity percent:  uint8, 0~100
Coverage percent:  uint8, 0~100
```

字段长度：类型 `1 B` + 数据 `6 B`。

错误语义：

- `Average = 0xFFFF, Max = 0`：无有效采样。
- `Coverage = 0`：本窗口没有有效采样覆盖。
- `Coverage < 100`：低功耗模式或缺采样，平台需降低统计置信度。

周期上报保留步数，不再默认上报瞬时 X/Y/Z。

### 8.2 告警事件

新增类型 `0xB1`：

```text
Type:        0xB1
Event no:    uint8, rolling sequence
Event flags: uint8
             bit0: delayed retry
             bit1: FIFO overrun occurred in window
             bit2~7: reserved, 0
Delay:       uint16, 分钟
             0      = 即时事件（本帧上行时事件刚发生，不足 1 min）
             1~32767 = 事件发生在本帧上行前 N 分钟（量程约 22.8 天）
             0xFFFF = 时间未知（换算超出量程或缓存重建）
Peak:        uint16, mg, raw magnitude
Dropped:     uint8, 自上次成功上行告警后被缓存丢弃的事件数
```

字段长度：类型 `1 B` + 数据 `7 B`。

- `Delay` 由设备按第 5.5 节回绕安全时间差换算，解决延迟补报缺少事件发生时间的问题；平台按"本帧接收时间 − Delay"还原事件发生时间。
- `uint16` 量程 0~32767 min 与 `ms_uptime < 2^31 ms`（约 35791 min）的换算前提一致；超过 32767 min（如设备长时间断网运行）上报 `0xFFFF`，平台按时间未知处理，不得回退为 0。
- 平台不应只依赖告警帧中的峰值判断事件时间；延迟补报时必须结合 `delayed retry` 标志与 `Delay` 字段。
- `Dropped` 非零表示事件缓存溢出丢弃过事件，告警历史不完整；计数**饱和于 255**，不回绕。
- `Event no` 为设备本次开机内的滚动序号，**重启后清零重新滚动**；平台不得跨重启用 `Event no` 去重（应以"接收时间 + Delay 还原的事件时间 + 序号"组合判重），序号仅用于同一运行期内的事件排序与去重。

### 8.3 ACC 配置写入

新增下行类型 `0xB2`：

```text
Type:                        0xB2
Flags:                       uint8
                              bit0: persist（写入持久化存储并立即生效）
                              bit1: temporary（仅 RAM 生效，重启回旧配置）
Sampling mode:               uint8, 0=continuous, 1=low power
Low power sampling rate:     uint8, Hz，低功耗模式稀疏采样率
Active sampling rate:        uint8, Hz，连续模式采样率；低功耗模式升频目标
Full scale:                  uint8, 0=±2g, 1=±4g, 2=±8g
Activity threshold:          uint16, mg
Alarm enable:                uint8
Alarm threshold:             uint16, mg
Alarm debounce duration:     uint16, unit 10 ms
Alarm quiet period:          uint16, min
High frequency hold:         uint16, s
Alarm Class C window:        uint16, min
Continuous timeout:          uint16, min, 0=disabled
Diagnostic duration limit:   uint16, min, 50 Hz 诊断模式最长持续时间
```

字段长度：类型 `1 B` + 数据 `22 B`。

**Flags 语义（定稿，不再保留实现期二选一）**：

| bit1 | bit0 | 语义 | 合法性 |
|---|---|---|---|
| 0 | 1 | persist：写持久化存储并立即生效 | 合法 |
| 1 | 0 | temporary：仅 RAM 生效，重启恢复旧持久化配置 | 合法 |
| 0 | 0 | 等效 temporary（仅本次生效，不写存储） | 合法 |
| 1 | 1 | flags 冲突 | 非法，返回错误码 2 |

**双采样率说明（定稿）**：`Low power sampling rate` 与 `Active sampling rate` 是两个独立字段，分别对应第 4.3 节的 `low_power_sampling_rate_hz` 与 `active_sampling_rate_hz`；连续模式只消费后者，低功耗模式消费两者。不允许单字段复用。

**硬件唤醒参数（定稿）**：不在协议中提供独立配置字段。硬件唤醒阈值和持续时间由告警阈值按第 4.3.3 节规则推导（`alarm_threshold / 2`、1 个 ODR 周期），平台无法单独配置；调整告警阈值即联动调整硬件唤醒灵敏度。

### 8.4 ACC 配置读取与上报

新增类型 `0xB3`：

- 平台下发 `0xB3` 且无数据，表示读取当前配置。
- **返回帧定稿为复用完整 `0xB2` 帧格式**（含 `Flags` 与全部字段，长度与 `0xB2` 相同），平台解码器复用 `0xB2` 解码逻辑。
- 返回帧 `Flags` 表示当前生效配置的来源：
  - `01`：当前运行为持久化配置。
  - `10`：当前运行为临时配置（如 50 Hz 诊断模式）。
  - `00`：出厂/默认运行态——Flash 校验失败回默认配置且尚未持久化的状态（如新设备首次上电、迁移后未写入前）。
- 其余字段返回当前实际运行值（含运行时推导值，如临时修改后的阈值），不返回持久化副本。

### 8.5 LoRaWAN Class 配置

新增类型 `0xB4`：

```text
Type:        0xB4
Class:       uint8, 0=Class A, 2=Class C
Persist:     uint8, 0=temporary, 1=persist
```

`Class` 仅接受 `0` 与 `2`；`1`（Class B）及其他值一律返回错误码 1（参数范围错误），不改变当前配置。切换 Class C 后设备需返回当前实际配置。

### 8.6 ACK 与错误

非法配置返回失败 ACK，不写持久化存储，不改变 RAM 配置。

**能力口径与帧布局（定稿）**：现有 ACK 机制只有成功样式（`0xFF`），错误码 ACK 是本设计新增能力，平台侧需要同步开发解析与展示。新帧布局：**ACK 数据域第 1 字节为错误码**，无额外数据；旧 `0xFF` 成功样式废止，成功以错误码 `0x00` 表示（平台与设备同步升级，见 CR-20）。

| 错误 | 含义 |
|---:|---|
| 0 | 成功 |
| 1 | 参数范围错误 |
| 2 | flags 冲突 |
| 3 | 持久化写入失败 |
| 4 | 传感器配置失败（含读回验证失败） |
| 5 | LoRa 模组状态错误 |

## 9. 配置校验

| 参数 | 默认 | 允许范围 |
|---|---:|---|
| 采样模式 | 连续 | 连续、低功耗 |
| 低功耗采样率 `low_power_sampling_rate_hz` | 1 Hz | 1、10 Hz |
| 连续/升频采样率 `active_sampling_rate_hz` | 25 Hz | 10、25、50 Hz（50 仅限临时） |
| 量程 | ±4g | ±2g、±4g、±8g |
| 活动阈值 | 250 mg | 50~1000 mg |
| 告警开关 | 开 | 开、关 |
| 告警阈值 | 750 mg | 100~3000 mg |
| 告警防抖 | 120 ms | 10~2000 ms |
| 静默期 | 10 min | 1~1440 min |
| 高频保持 | 60 s | 10~300 s |
| 告警后 Class C 窗口 | 5 min | 1~60 min |
| 连续模式超时 | 关闭 | 0 或 10~1440 min |
| 诊断模式最长持续时间 | 30 min | 1~1440 min |

额外约束：

1. 告警阈值应允许低于活动阈值，由平台自行决定是否如此配置。
2. 采样率必须是 LIS3DH 支持的 ODR。
3. `50 Hz` 只能以临时生效方式配置为 `active_sampling_rate_hz`（诊断/追踪用途，边界见第 4.3.1 节）；持久化配置请求包含 `50 Hz` 时返回参数范围错误。
4. 配置切换量程或采样率时，应先关闭中断、清 FIFO、写传感器、读回验证，再恢复采样。
5. 传感器写失败时保持旧配置并返回失败。
6. 双采样率字段独立校验、互不联动；不允许通过单一字段同时修改两个采样率。

## 10. 配置持久化

### 10.1 存储介质选型（定稿：主 Flash 尾部空闲区）

**ACC 配置存放在主 Flash 用户参数区尾部空闲区 `0x0800FC00`**，不使用片内 EEPROM。选型理由：

1. 复用现有 `flash.c` 读写基础设施与产线/运维工具链对主 Flash 参数区的既有约定，不引入新存储路径。
2. `0x0800FC00` 同时是 1 KB 逻辑分区边界和 128 B 物理页边界；配置结构 32 B（见第 10.2 节）只占用首个物理页 `0x0800FC00~0x0800FC7F`，擦除范围独立，不影响相邻逻辑分区的写入。
3. 写入频率低（部署调优期每天少于 10 次，稳态远低于此），单物理页 1 万次擦写寿命按每天 10 次估算约 2.7 年，稳态使用无压力；相同配置不写进一步降低擦写次数。

**主 Flash 物理页与逻辑分区关系（实现必须遵守）**：STM32L0 物理擦除单位为 128 B 页；工程宏 `FLASH_ONE_PAGE_SIZE = 0x400`（`USER/Drive/include/flash.h:13`）是 1 KB 逻辑分区步长，不是物理页。用户参数区 `0x0800E000 ~ 0x08010000` 共 8 KB，现有逻辑分区后尾部约 2 KB 空闲。ACC 配置区擦除只擦自身 128 B 物理页，禁止按 1 KB 逻辑分区整段擦除。

**页擦除停顿的实时性缓解**：主 Flash 页擦除（128 B 典型 2~3 ms）期间停顿取指，可能干扰 FIFO 批处理时限。缓解规则：配置写入（含擦除）必须安排在 FIFO 批处理刚完成后的时间窗执行，且拆为"擦除 → 编程 → 回读"多步进执行，任何单步不超过 10 ms。可用窗口按当前采样率重算：25 Hz（watermark 25）批次间隔约 1.0 s；50 Hz（watermark 12）批次间隔约 0.24 s——10 ms 步进在两种档位下均可容纳，但 50 Hz 下写入步进必须与批处理交错调度，不得连续执行多步。恢复出厂与启动时写入无此约束（采样任务尚未运行）。

### 10.2 存储结构

```c
typedef struct __attribute__((packed)) {
    uint16_t magic;
    uint8_t  version;
    uint8_t  sampling_mode;
    uint8_t  low_power_sampling_rate_hz;  /* 与 0xB2 低功耗采样率对应 */
    uint8_t  active_sampling_rate_hz;     /* 与 0xB2 连续/升频采样率对应 */
    uint8_t  full_scale;
    uint16_t activity_threshold_mg;
    uint8_t  alarm_enable;
    uint16_t alarm_threshold_mg;
    uint16_t alarm_debounce_duration_10ms;
    uint16_t alarm_quiet_period_min;
    uint16_t high_frequency_hold_s;
    uint16_t alarm_class_c_window_min;
    uint16_t continuous_timeout_min;
    uint16_t diagnostic_duration_limit_min;
    uint16_t crc16;
    uint8_t  pad[6];                      /* 对齐填充至 32 B */
} acc_config_storage_t;   /* 共 32 B，位于 0x0800FC00 首个 128 B 物理页 */
```

**存储细节（定稿）**：

1. 结构总长 32 B，与现有 `FLASH_Write_NWord()` 按字（4 B）写入的接口对齐，8 word 一次写完，无字节拼装。
2. CRC 算法：CRC16-CCITT，多项式 `0x1021`，初值 `0xFFFF`，无反射无异或输出；覆盖范围为 `magic` 起至 `pad` 前的全部字段（不含 CRC 自身与 pad）。
3. `pad` 固定写 `0x00`，不纳入 CRC（擦除态为 `0xFF`，编程即显式写 0，不产生未定义值）。
4. 双采样率必须作为两个独立字段持久化，与 `0xB2` 一一对应；不得回退为单字段复用。

Class A/C 已有持久化入口，可继续使用现有 LoRaWAN 配置存储；如实现上更清晰，也可并入上述结构并升级版本。

### 10.3 写入规则

平台配置频率为低频，预计每天少于 10 次。写入按"擦除自身 128 B 物理页 → 编程 → 回读"执行，并遵守第 10.1 节实时性缓解规则。

写入前必须：

1. 校验参数范围。
2. 校验 flags。
3. 比较新旧配置，完全相同则不擦写。
4. 写入 magic、version、CRC。
5. 回读校验。

读取时：

1. CRC 和参数范围错误则使用默认配置。
2. 配置版本升级时执行显式迁移或回默认值。
3. 不允许半初始化结构进入运行态。

按每天 10 次擦写估算，单物理页 1 万次寿命约可用 2.7 年；部署调优期结束后写入频率远低于该值，寿命压力更低。禁止把运行态、防抖计数或告警队列写入持久化存储。

### 10.4 读取、启动时序与存量迁移

启动时读主 Flash 配置区：CRC 与范围校验通过后按配置初始化 LIS3DH（含 `FDS=0` 数据通路、`HPIS1=1` 中断判定通路、ODR、量程、FIFO/watermark、AOI），再进入采样任务；校验失败回默认配置。模组 Class 配置同样在启动时读取并应用。

**存量设备迁移（定稿）**：现有固件持久化的调度配置默认为 30 min，与本设计 10 min 默认口径不同。三种路径的处理：

| 路径 | 调度周期来源 | 说明 |
|---|---|---|
| 新设备 / 重新烧写 | 新固件默认 10 min | 出厂即新口径 |
| 恢复出厂 | 全部配置（含调度）回默认 10 min | 第 10.5 节 |
| 存量设备 OTA/烧写升级 | **首次进入新固件时迁移为 10 min** | 以 ACC 配置区 `magic` 无效作为"新固件首次运行"标志：此时写 ACC 默认配置，同时将调度周期重置为 10 min 默认并持久化，随后主动上报一次当前配置供平台确认 |

迁移规则说明：存量 Flash 中的 30 min 是旧出厂默认，无法与运维显式配置区分；按"重置为 10 min + 上报"处理，若该设备确有 30 min 运维需求，平台收到上报后重新下发即可（配置下发频率每天少于 10 次，成本可接受）。迁移只执行一次（`magic` 写入后不再触发）。

**迁移写入顺序（断电一致性，定稿）**：先持久化调度周期 10 min 并回读成功，再写 ACC 默认配置（含 `magic`）。两步之间断电时 `magic` 仍无效，下次启动重新迁移——调度迁移重入幂等（再写一次 10 min 无副作用），不会出现"magic 已写但调度永久停留 30 min"的不一致。禁止反向顺序。

### 10.5 恢复出厂设置

现有恢复出厂逻辑（下行触发 `restFactorySign` → `control_center.c` factoryEvent 路径）只恢复运行周期等配置，未覆盖新增 ACC 配置。定稿要求：

1. 恢复出厂必须同时恢复 ACC 全部配置默认值：采样模式、双采样率、量程、活动阈值、告警开关/阈值/防抖/静默期、高频保持、Class C 窗口、连续超时、诊断时长。
2. 恢复 Class A/C 配置默认值（Class A）。
3. 写回主 Flash 配置区（magic/version/CRC 更新），并重新初始化传感器（按默认配置重配 LIS3DH 与中断）和模组（Class A、确认模式）。
4. 恢复出厂后清除事件缓存与丢弃计数。
5. 测试计划见第 13.4 节。

## 11. 功耗设计

### 11.1 运行架构口径（定稿）

**第一版架构：入网后 MCU 常醒**（与当前固件行为一致）。既有 `10 min @ 2.2 mA` 基线即为 MCU 常醒口径。连续 ACC 常开的增量（LIS3DH 25 Hz 工作电流数百 μA 量级，以数据手册为准，加上 I2C 批读与统计计算开销）必须在该口径下实测，写入验收。

**后续优化项（默认不实现）：入网后 Stop + FIFO 浅唤醒**。该架构必须先完成第 15.2 节睡眠架构 POC。若引入，浅唤醒路径不得沿用当前 Stop 后全量重初始化时钟、UART、I2C 的流程，必须按唤醒源区分处理：

| 唤醒源 | 唤醒后动作 |
|---|---|
| RTC 周期唤醒 | 检查窗口/上报到期，按需处理 |
| ACC FIFO 唤醒（INT2 watermark） | 只读 FIFO、更新统计、快速回睡；不触发 GPS、LoRa、串口全量重建 |
| 告警事件唤醒（INT1 AOI） | 升频采样 + 软件复判，确认告警才拉起 LoRa 流程 |
| 按键或外部事件唤醒 | 全量恢复运行态 |

每秒一次 FIFO 唤醒的电荷开销必须实测达标后才允许切换默认架构。

### 11.2 估算

仓库既有模型：

| 周期 | 平均电流 | 38000 mAh 寿命 |
|---:|---:|---:|
| 1 min | 约 19 mA | 约 66 天 |
| 5 min | 约 4.1 mA | 约 300 天 |
| 10 min | 约 2.2 mA | 约 575 天 |

本设计新增估算（待实测修正）：

| 场景 | 平均电流估算 | 38000 mAh 名义寿命 |
|---|---:|---:|
| 10 min 上报 + 默认连续 ACC 25 Hz | 约 2.35~2.5 mA | 约 530~550 天 |
| 10 min 上报 + 低功耗 ACC | 约 2.25~2.35 mA | 约 550~575 天 |
| 常驻 Class C | 约 6.4~17.4 mA（基线约 2.4 mA + 接收额外约 4~15 mA） | 约 2.1~6.5 个月（见 11.3） |

### 11.3 常驻 Class C 寿命（修正）

常驻 Class C 平均电流 = 基线约 `2.4 mA` + 接收额外 `4~15 mA` = 约 `6.4~17.4 mA`：

| 有效容量折算 | 38000 mAh 对应寿命 |
|---|---:|
| 80%（30400 mAh） | 约 2.4~6.5 个月 |
| 70%（26600 mAh） | 约 2.1~5.7 个月 |

此前版本所列"约 12~28 个月"计算有误（遗漏基线电流叠加），已废止。常驻 Class C 不纳入默认验收，但上述数字用于平台与运维决策，必须按实测修正；`4~15 mA` 范围过宽，需先查模组规格书标称 RX 电流，再按第 15.2 节 Class C 电流 POC 实测告警后 5 分钟窗口的实际平均电流，收窄区间后更新本表。

### 11.4 资源红线

当前 map（`USER/Listings/LoRaWAN_Animals_Track.map`）：ROM 约 `53.84 KB / 64 KB`，RW+ZI 约 `7.12 KB / 8 KB`。余量不允许随意引入 float FIFO 数组、CMSIS-DSP 库、复杂队列抽象或大量调试字符串。

红线（每个实现阶段记录 map 并检查）：

1. 新增功能 RAM 增量 ≤ `512 B`；总 RW+ZI 不超过 `7.6 KB`（保留栈与堆余量）。
2. 新增功能 ROM 增量 ≤ `4 KB`；总 ROM 不超过 `58 KB`。
3. 超线必须回到设计评审，不得静默接受。
4. 实时路径禁止浮点格式化日志（体积与执行时间双重回退）。

### 11.5 验收口径

- 默认连续 25 Hz + 10 分钟定位/上报，实测平均电流不超过约 `2.5 mA`（MCU 常醒口径）。
- 按电池有效容量 70%~80% 折算。
- 最低实际寿命 12 个月。
- 设计目标 15 个月。
- `50 Hz` 不纳入长期电池寿命验收；仅用于平台显式开启的短时诊断或追踪，退出后恢复持久化采样率。
- 若默认模式实测超过 `2.5 mA`，优先降低默认采样率、收紧诊断模式持续时间或拉长周期上报间隔。

注意：告警频繁触发时，主要功耗来自 LoRa 上行和 Class C 接收，不是 25 Hz ACC 采样。防抖和静默期必须严格生效。

## 13. 测试计划

### 13.1 单元与算法测试

1. 合成 X/Y/Z 数据验证平均幅值、最大幅值、活动百分比、覆盖率。
2. 静止数据验证合成幅值约为 `1g`（HPF 数据通路 `FDS=0` 前提下的回归用例；同时验证 `FDS=1` 误开时该用例必须失败）。
3. `abs(magnitude - 1g)` 分别高于、低于 `250 mg` 时验证活动分类。
4. 峰值超过 `750 mg` 且持续时间不足 `120 ms` 时不触发告警。
5. 持续 `120 ms` 以上超过 `750 mg` 时触发告警。
6. 在 25 Hz、50 Hz 下分别验证同一防抖持续时间语义一致。
7. 静默期内不重复上行，但统计继续更新。
8. 窗口边界生成快照后，下一窗口样本不重复或漏计。
9. **时间回绕测试**：将 `ms_uptime` 置于 `0xFFFFFFFF` 回绕点附近（用注入计数方式模拟，不实际等待 49.7 天），验证防抖、静默期、窗口到期、发送超时和事件 `Delay` 换算不误判；同时回归验证新增代码未误用 `get_syspant_ms()` 时基（`86400000` 清零点）。
10. **变速窗口覆盖率**：窗口内 1 Hz ↔ 25 Hz 多次切换，`expected_samples` 按分段结算，覆盖率在 95%~105% 区间（允许取整误差），不得用窗口末采样率反推。
11. **窗口边界快照**：快照生成、累加器清零与并发新样本不重复不漏计（含变速瞬间触发的结算）。
12. **FIFO overrun 后覆盖率**：注入 overrun，验证覆盖率按缺口扣减、overrun 标志上报、缺失时间不被推断为活动或非活动。
13. **长窗口累加溢出**：按 `25 Hz + 1440 min` 满量程合成数据（幅值 `13856 mg`）验证 64 位累加器不溢出、平均值正确。
14. **1 Hz 段不产生告警**：稀疏段单点越限不直接触发告警，升频后软件复判决定。
15. **`expected_samples` 乘法宽度**：注入 `86400000 ms × 50 Hz` 段（诊断模式最大窗口）验证 64 位中间量结果正确（4 320 000），不发生 32 位中间溢出截断。

### 13.2 传感器测试

1. 25 Hz FIFO watermark 25 级批读，覆盖率接近 100%；中断到批处理完成实测小于 250 ms（理论上限 280 ms）。
2. FIFO overrun 后能清空并恢复（stream 模式语义，见第 5.2 节）。
3. 量程在 ±2g、±4g、±8g 间切换并读回验证；读回不符时保持旧配置。
4. 低功耗模式 1 Hz（watermark 10 级）与运动后升频切换正确；AOI INT1 唤醒后立即升频，不等 watermark。
5. 连续 60 s 无运动后自动降回 1 Hz。
6. INT 路由验证（按第 4.3.3 节选定方案）：主方案下 AOI 与 watermark 同路由 INT1，软件读 `INT1_SRC`/`FIFO_SRC` 能正确区分两类事件；若启用可选增强，验证 watermark 只出现在 INT1、AOI 只出现在 INT2。
7. **AOI 静止零触发回归（P0 回归用例）**：设备静止任意姿态放置 10 min，AOI 触发次数为 0（验证 `HPIS1=1` 滤重力配置正确；若误用原始数据判定，该用例必失败）。
8. **模式切换后静止不误升频**：静止设备上反复执行 1 Hz ↔ 25 Hz 升降频（含第 4.3.3 节 HPF 复位序列），滤波器建立期不触发 AOI、不产生升频；缺少复位序列的对照实现应能被该用例检出。
9. 硬件唤醒阈值推导验证：修改告警阈值后 AOI 阈值按 `alarm_threshold / 2`（限幅 125~1000 mg）联动，并按 `INT1_THS` 量化（±4g 下 1 LSB=32 mg，默认生效 384 mg）。
10. `lis3dh_set_mode()` 写成功返回 `true`；配置失败回滚逻辑用正确返回值验证。
11. I2C 异常（模拟传感器不应答）时读写超时返回，连续失败置传感器故障标志，主循环不死等。
12. 低速 MCU 时钟下测量 FIFO 批读、统计计算和主循环最大延迟。
13. 25 Hz 高频保持窗口连续运行 60 s，FIFO overrun 为 0。
14. **50 Hz 诊断模式连续运行 30 min**：watermark 12、批次间隔 0.24 s，FIFO overrun 为 0，中断到批处理完成 < 250 ms；退出后恢复持久化采样率。

### 13.3 LoRa 告警测试

1. 事件唤醒后典型 1 min 内上行。
2. 网络失败时缓存，恢复后补报；补报帧 `Delay` 字段还原的事件时间与实际发生时间偏差不超过 1 min。
3. 告警上行不阻塞周期统计。
4. LoRa 发送期间持续读取 ACC FIFO，统计窗口继续累加。
5. LoRa 发送失败时已生成的周期摘要快照可恢复补发。
6. Busy 异常时有超时，不死机。
7. 告警成功（confirmed uplink 判据）后 Class C 窗口打开 5 min 并自动关闭；Class 切换全程非阻塞，无 7.5 s 卡顿。
8. Class A 常态下平台下行仅在 RX 窗口生效。
9. 告警独立退避验证：60 s 起指数退避，不与 30 分钟重连退避叠加；模组明确掉网时才转入重连。
10. 事件缓存溢出：缓存满 8 条后丢最旧，`Dropped` 字段正确上报递增计数。
11. 平台 ACK 上行与告警发送并发时按优先级排队，均不阻塞。

### 13.4 配置测试

1. 各参数合法范围边界值测试。
2. 非法参数返回失败 ACK（含错误码），不写 Flash，不改 RAM。
3. 持久化配置重启后生效。
4. 临时生效配置重启后恢复旧持久化配置。
5. 重复下发相同配置不擦写 Flash。
6. 配置区 CRC 破坏后回默认配置。
7. 配置写入只擦除 `0x0800FC00` 自身 128 B 物理页，验证相邻逻辑分区数据不受影响；写入后 FIFO 批处理时限仍满足 250 ms 实测红线（25 Hz 与 50 Hz 档位分别验证）。
8. 持久化配置 `50 Hz` 被拒绝，临时配置 `50 Hz` 只在当前运行态生效；诊断模式超时（默认 30 min）、平台下发、重启三种退出路径均恢复持久化采样率。
9. 双采样率独立配置：修改 `low_power_sampling_rate_hz` 不影响 `active_sampling_rate_hz`，反之亦然；`0xB2` 全零 flags 等效临时生效；flags `11` 返回错误码 2。
10. `0xB3` 返回帧复用完整 `0xB2` 格式，flags 表示配置来源（01 持久化 / 10 临时）。
11. **恢复出厂**：恢复出厂后 ACC 采样、量程、阈值、告警、Class 配置全部回默认值，传感器与模组重新初始化，事件缓存清空。
12. **存量升级迁移**：预置旧固件 30 min 调度配置的设备升级到新固件，首次启动检测 ACC 配置区 `magic` 无效，调度周期迁移为 10 min 并持久化、上报配置；二次启动不再重复迁移；平台重新下发 30 min 后按 30 min 运行。

### 13.5 功耗与稳定性

1. 默认模式实测平均电流不超过 `2.5 mA`（MCU 常醒口径）。
2. 模拟 LoRa 长时间 Busy 或失败路径，ACC 统计仍持续更新。
3. 连续运行至少 72 h 无复位、无 FIFO 卡死、无告警队列溢出。
4. Stop/唤醒循环测试（未入网空闲路径，验证不入网态行为不回退）。
5. LoRa 失败重试和恢复测试。
6. 低温或实际部署环境下复核电池有效容量。
7. 若实现短时升频，对比低速长批处理与高速短批处理的平均电流和能量消耗。
8. 每实现阶段记录 RAM/ROM map，对照第 11.4 节红线检查。

## 14. 主要风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 量程饱和 | 最大幅值削顶 | 默认 ±4g，现场必要时切 ±8g |
| 采样缺口 | 统计置信度下降 | 上报覆盖率，平台按覆盖率解释 |
| 告警误报 | 电池消耗和业务干扰 | 独立高阈值、120 ms 时间防抖（仅高频段判定）、10 min 静默期 |
| LoRa Busy / Class 切换 / I2C 卡死 | 设备无法继续采样和告警，FIFO overrun | 全路径异步状态机 + 统一超时 + I2C 失败计数（第 7 章） |
| 长窗口累加器溢出 | 平均值错误 | 64 位累加器（第 5.1 节容量证明） |
| 毫秒计数跨零 | 防抖/静默期/窗口误判 | 回绕安全时间差函数（第 5.5 节） |
| Stop 后误重新入网 | 告警时延增加 | 保留模组会话状态，仅确认真丢失会话才重连；依赖会话 POC（第 15.2 节） |
| 持久化磨损 | 配置区寿命缩短 | 单 128 B 物理页独立擦写、相同配置不写、低频持久化、运行态不入存储 |
| 资源超线 | 无法构建或栈溢出 | 第 11.4 节 RAM/ROM 红线与阶段 map 检查 |
| Class C 常驻 | 电池寿命明显下降（约 2.1~6.5 个月，第 11.3 节） | 默认 Class A，仅告警后短窗口或运维模式开启 |

### 15.3 验收红线

1. 默认 `10 min + 连续 25 Hz` 实测平均电流不超过 `2.5 mA`（MCU 常醒口径）。
2. 25 Hz 高频窗口连续 60 秒 FIFO overrun 为 0；50 Hz 诊断模式连续 30 min FIFO overrun 为 0。
3. 25 Hz（watermark 25）与 50 Hz（watermark 12）下，中断到完成 FIFO 批处理的实测时间均小于 250 ms；各自理论上限（280/400 ms）不得触碰。
4. LoRa Busy 异常、I2C 异常和 Class 切换异常均有超时，不得阻塞 ACC 统计。
5. 告警上行和周期摘要发送失败不污染下一窗口统计。
6. 延迟补报能还原事件发生时间（`Delay` 字段 uint16，量程 0~32767 min；误差不超过 1 min；超量程上报 `0xFFFF` 按时间未知处理）。
7. 协议允许的最大窗口（`25 Hz + 1440 min`）不发生累加器溢出，`expected_samples` 中间乘积不发生 32 位截断。
8. 恢复出厂后 ACC 和 Class 配置全部回到默认值；存量升级路径调度周期按第 10.4 节迁移。
9. 每阶段 RAM/ROM map 不超过第 11.4 节红线。
