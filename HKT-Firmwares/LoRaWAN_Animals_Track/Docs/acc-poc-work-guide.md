## 4. 任务 A：原理图 INT2 走线人工对图

### 4.1 背景

- 设计文档 §4.3.3 的 INT 路由主方案为单 INT1 多事件（`I1_IA1`+`I1_WTM` 同路由 INT1/PB7），若 INT2 已接入 MCU 可启用可选增强（INT1=watermark、INT2=AOI1 经 `CTRL6.I2_AOI1`）。
- PDF 文本提取显示 INT2 网络标签仅出现一次且紧邻测试点 TP10，未见第二处接入 MCU；固件侧 `EXTI4_15_IRQHandler`（`gpio.c:100-115`）只处理 LINE_7 一路 ACC EXTI。**文本提取无法看到导线连接，必须人工对图确认。**

### 4.2 对图步骤

1. 打开 `LL_V02原理图_0205.pdf`，定位 LIS3DH 器件页，找到 `INT2` 引脚，记录其网络标签名称（如 `ACC_INT2`/`INT2`）。
2. 在全文档搜索该网络标签，列出**全部**出现位置（页码 + 坐标区域）。
3. 逐处判别连接对象：
   - 仅测试点（TP10）/上拉电阻/悬空 → INT2 未接 MCU；
   - 连接到 STM32L051C8 任一 GPIO → 记录引脚号与端口名（如 `PB_x`），并在 MCU 引脚复用表中核对该引脚无其他占用。
4. 顺带核对 INT1 走线：确认 INT1 连接的 MCU 引脚即 PB7（与固件 LINE_7 一致），记录上拉电阻阻值（POC-2 I2C/INT 信号质量参考）。
5. 核对 PCB 实物版本与 LL_V02 原理图一致性（板号丝印），不一致时以实物 PCB 网络表为准并注明差异。

## 5. POC-1：模组会话保持与 Class/模式切换耗时

### 5.1 目的

验证设计文档 §7.2-5（Stop 前保存会话、唤醒后不重新入网）的模组行为基础，并校准 §7.1 状态机超时表。对应风险：会话不能保持 → 事件唤醒后重连，告警时效（CR-13）失效。

### 5.2 前置条件与设备

- 整机样板 ≥1 台（模组 LSD4WN-2L817M90，记录 AT 固件版本，查询命令见模组使用说明书）；
- 串口调试工具（可发 AT 命令、记录时间戳）；有条件时用逻辑分析仪挂在模组 UART RX/TX 上测耗时；
- 可用 LoRaWAN 网关（记录网关型号、频段——注意规格书为 EU868 版本，确认样板实际频段与固件 hex 版本 AU915/EU868 一致性，不一致时先解决频段问题再测）。

### 5.3 步骤

1. **版本与基线记录**：读模组 AT 固件版本、入网（AT+JOIN 或现有固件入网流程），记录入网耗时与入网后 RSSI/SNR（如模组支持查询）。
2. **会话保持循环测试**（核心项，≥10 次循环）：
   1. 模组进入睡眠（按说明书睡眠命令，或复用现有固件 Stop 路径的模组睡眠调用）；
   2. 保持 ≥10 s 后唤醒；
   3. 用**状态查询命令**确认是否仍处于已入网态（候选命令：入网状态查询、`AT+CLASS?` 回包内容、模组状态脚电平——逐一验证哪个能可靠区分"已入网/未入网"，这本身是本 POC 要得出的结论之一）；
   4. 记录每次结果；随后发一条 confirmed uplink 验证会话真正可用（能收到网络 ACK 才算有效保持）。
3. **会话丢失判定与回退**：人为制造会话丢失（模组硬复位 / 断电重启），重复步骤 2-3 的查询，确认步骤 2 选定的判据能正确报告"未入网"；记录重新入网耗时。
4. **命令模式 ↔ 透传模式切换耗时**：各测 10 次，记录单次耗时与最坏值（逻辑分析仪或串口时间戳）。
5. **Class 切换耗时**：`AT+CLASS` A↔C 各 10 次，记录单次命令-回包耗时；再按现网重试结构（1.5 s 超时 ×3 + 1 s 延时）模拟最坏阻塞，对照设计文档引用的 7.5 s。
6. **确认重传时长**：confirmed uplink 在弱信号下（可加大距离/加衰减）观察模组重传行为与总耗时，用于校准 §7.1 的 `SEND_WAIT_STATUS` 30 s 初值。

## 6. POC-2：ACC 批处理时限验证（含 AOI、I2C 速率、HPF 建立时间）

### 6.1 目的

在设计文档 §5.4 的 250 ms 红线与 §4.3.3 的 AOI 配置进入实现前，用 1.048 MHz 实际主频验证：批处理耗时、零 overrun、AOI 静止零触发、I2C 400 kHz 信号完整性、1 Hz 档 HPF 建立时间。

### 6.2 打桩固件要求（最小实现，不依赖正式驱动修复）

1. LIS3DH 初始化：HPF 配置为 `FDS=0` + `HPIS1=1`（数据原始、AOI 判定滤波）、AOI 六事件 OR、阈值 `INT1_THS=12`（±4g 下 384 mg）、`duration=1`、锁存开；FIFO stream 模式。
2. 批量读：一次 I2C 事务按 `FIFO_SRC.FSS` 读 `num*6` 字节（地址自动递增）。本 POC 需先实现该函数（打桩版），正式驱动修复（§15.1 步骤 5）可在 POC 结论后进行。
3. 整数开方 `isqrt32` 打桩实现（逐位或牛顿迭代）。
4. GPIO 打桩：批处理路径上翻转两个 GPIO——`GPIO_T0`（EXTI 进入/中断置位检出点）、`GPIO_T1`（批处理完成点），供逻辑分析仪/示波器测量"中断→完成"时长；另两个 GPIO 标记 I2C 段与计算段。
5. EXTI 方案按任务 A 结论配置（主方案：`I1_IA1`+`I1_WTM` 同路由 INT1；可选增强：分脚）。
6. 超时与错误计数打桩：I2C 事务失败时记录并重试，不挂死。

### 6.3 步骤与工况

1. **主频确认**：读 RCC 寄存器确认 MSI 1.048 MHz 实际生效，记录。
2. **25 Hz 批处理耗时**（watermark 25）：
   - 静置工况：连续 ≥100 批，记录每批 I2C 段耗时、isqrt+统计段耗时、单批总耗时（min/max/avg）；
   - 并发工况：叠加周期定时器、GPS 解析桩、模拟 LoRa 状态机轮询桩运行时的单批最大"中断→完成"时长（对应红线 250 ms 的真实路径）。
3. **60 s 零 overrun**：25 Hz 连续 60 s，每秒读 `FIFO_SRC.OVRN`，统计 overrun 次数（预期 0）。
4. **50 Hz 诊断档**（watermark 12）：重复步骤 2 并连续 30 min 零 overrun。
5. **AOI 静止零触发**：设备静止、任意安装姿态（至少测 3 个姿态：水平、侧立、倒置）各 10 min，读 `INT1_SRC` 统计触发次数（预期 0；非 0 说明 HPF 判定通路配置错误，回查 `HPIS1`）。
6. **I2C 400 kHz 信号完整性**：
   - 先按当前默认速率（100 kHz）测一批作基线；
   - 重配 TIMINGR 至 400 kHz（按 rm0377 公式与上拉阻值计算，记录计算值），示波器观察 SCL/SDA：上升沿时间、高电平幅度、有无过冲振铃；
   - 连续 10 min 批读，比对回读寄存器值（如 WHO_AM_I、参考寄存器）与预期，统计误码/超时次数（预期 0）。
7. **1 Hz 档 HPF 建立时间**（对应设计文档 §4.3.3 步骤 5 丢弃窗口）：
   - 1 Hz ODR + `HPIS1=1`，复位 HPF（读 `REFERENCE`）后开始计时；
   - 静止状态下记录 AOI 误触发持续的时长（若有），以及 HPF 输出稳定（`INT1_SRC` 不再置位）所需时间；
   - 用 25 Hz 档重复一次作对照，验证"建立时间 ∝ 1/ODR"的倍率关系；
   - 结论换算为"丢弃 N 个 ODR 周期"，N 为本项产出。

## 7. POC-3：睡眠架构平均电流口径

### 7.1 目的

实测设计文档 §11.1 定稿的第一版架构（入网后 MCU 常醒 + 连续 ACC）平均电流，验证 2.5 mA 红线；顺带量化低功耗模式收益，为模式价值决策提供数据。

### 7.2 前置条件与设备

- 整机样板 ≥1 台，电池供电改为稳压电源 + 电流测量仪（µA 级分辨率：源表 / Nordic PPK2 / Joulescope 任一，记录仪器型号与采样率）；
- 环境温度记录（室温即可，注明）；外设状态与实机一致（GPS 天线位置固定、模组接真实网络）；
- 测试固件：含 POC-2 的 ACC 打桩 + 周期上报逻辑；对照组用现网固件。

### 7.3 步骤

1. **方法学校准**：现网固件、10 min 周期、无 ACC 常开，测 ≥2 h 平均电流。对照既有基线 2.2 mA（`Docs/1_5_10分钟功耗寿命预估.txt`，单位按 mA 解释）——偏差 >10% 时先排查测量设置（供电电压、仪表采样率、是否有调试串口常开）再继续。
2. **连续模式**：新固件、25 Hz 连续 ACC、10 min 定位+上报，测 ≥2 h（建议 12 h 覆盖昼夜温度与网络波动）平均电流。
3. **低功耗模式**：1 Hz 常开 + AOI 唤醒逻辑，同工况测 ≥2 h 平均电流；期间每小时手动激励一次运动（触发升频保持 60 s）以覆盖升频路径。
4. **（可选，不作为第一版验收）Stop 浅唤醒对照**：如资源允许，按设计文档 §11.1 唤醒源分表实现最小浅唤醒原型，测同工况平均电流，仅作为后续优化决策输入。

## 8. POC-4：Class C 窗口电流

### 8.1 目的

收窄设计文档 §11.3 的 4~15 mA 估算区间：先查规格书标称，再实测告警成功后 5 min Class C 窗口的实际平均电流，重算常驻 Class C 寿命表。

### 8.2 前置条件

- POC-1 已确认 Class 切换命令可用；
- 设备同 POC-3（电流测量仪在线）；
- 网关可正常下行（Class C 接收窗口验证需要至少一次下行）。

### 8.3 步骤

1. **规格书标称**：查模组规格书 RX 电流（记录测试条件：频段、速率），与"基线 2.4 mA + 标称 RX"合成理论上限，预填 §11.3。
2. **实测**：设备入网、切 Class C，保持 5 min（含至少 1 次网关下行），电流仪记录窗口内平均电流；重复 3 次取均值与最坏值。
3. **合成**：`实测窗口平均电流 − 实测 Class A 常态平均电流` = Class C 增量；用增量替换 §11.2/§11.3 表中"额外约 4~15 mA"，按 80%/70% 有效容量重算寿命区间。

### 8.4 记录表 POC-4

### 8.5 判据

本 POC 无 pass/fail（常驻 Class C 不纳入默认验收），但**必须产出收窄后的区间并回填 §11.2、§11.3**，废止 4~15 mA 宽区间表述。
