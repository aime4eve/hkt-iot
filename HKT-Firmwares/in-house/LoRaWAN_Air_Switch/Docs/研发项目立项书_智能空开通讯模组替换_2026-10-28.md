## 一、项目背景

### 1.1 公司模组使用现状

公司自研物联网设备的通讯模组存在两条技术路线并行的情况：

1. **欧创固定频率模组**：用于自研智能车位锁设备。该设备系统测试未能通过，欧创模组路线已被验证无法作为公司自研物联网设备的基础平台。
2. **利尔达通讯模组**：公司在固定频率（动物追踪器 LSD4WN-2L817M90 等）和可变频率两类自研设备上均有基于利尔达模组的量产与实测经验，均无明显质量问题。

### 1.2 智能空气开关现状

公司自研智能空气开关（产品型号 SCB100，下称"空开"）当前基于**利尔达固定频率通讯模组**设计，主控为 GD32F103，模组通过 AT 指令驱动。固件按目标市场频段以编译开关出多套版本，现有频段配置覆盖 EU868、US915、AU915、CN470（三个子带）、IN865、AS923（三个子区）、KR920，当前软件版本 V7.14（2026-09-17）。

固定频率模组的使用方式存在两项结构性限制：

- **复用率低**：现固件采用"关闭 ADR、固定速率 DR3、固定信道组"的配置，每个目标频段各出一套固件版本并各做一次认证，市场越多、维护面越宽。
- **规模化受限**：固定信道把设备的发送集中在少数频点上。空开的主打市场在欧洲和北美，其中欧洲 868MHz 频段有每信道 1% 占空比的法规硬约束，设备量增长后，互扰恶化与占空比超标的风险都集中在固定频点上。

### 1.3 市场需求

公司自研智能空气开关设备在欧美市场持续有稳定购买需求，是智慧公寓（SmartBuilding）解决方案的主力设备之一。通讯模组的能力与合规性直接决定该产品线的市场准入与规模上限。

## 二、立项必要性

1. **平台归一是必然选择。** 欧创模组已因车位锁系统测试未通过而退出基础平台候选；利尔达模组在公司多条产品线上验证可靠。通讯模组收敛到利尔达一家，可统一技术支持、供货与认证资产。
2. **可变频率模组提升复用率。** 可变频率模组运行标准 LoRaWAN 跳频与信道管理，"一区域一固件版本"有机会收敛为一套固件加区域参数配置，降低跨区域版本的维护成本。复用率收益将在选型评审后量化（频段版本数收敛比例、模组驱动层复用比例）。
3. **可变频率是欧美市场规模化的前提。** 跳频把流量摊到全信道，既是抗干扰手段，也是满足欧洲占空比法规、支撑设备规模增长的手段。该条直接对应欧美市场的稳定订单需求。
4. **团队具备同类适配经验。** 固件模组驱动层已按"业务逻辑与指令集分离"的抽象层设计，2026 年 7 月刚完成一次"新增欧创模组指令集支持"的同类适配，本次替换有成熟的工程路径。

## 三、项目目标

### 3.1 总体目标

将智能空气开关（SCB100）的通讯模组由利尔达固定频率模组替换为利尔达可变频率模组，完成 PCB 重新设计、固件适配与系统测试，通过目标市场认证，达到小批量试产放行条件。

### 3.2 量化目标

| 指标 | 目标值 |
|---|---|
| 跨频段固件版本收敛 | EU868 / US915 共用同一套固件主体（区域参数配置化） |
| 上行报文兼容性 | 与现款 100% 一致，平台侧解码器零改动 |
| 入网成功率 | 标准场强环境（RSSI ≥ -100 dBm）≥ 99%（连续 100 次冷启动入网统计）；重入网恢复时间符合现款时序基线（超时约 120 s 判失败 → 退避 10 分钟 → 模组复位重试） |
| Class C 下行响应时延 | 按 5.4 测试集 P1/P2 两种工况实测，不劣于现款同环境基线的 120%（基线于 M1 建档） |
| 长稳运行 | 7×24 小时连续运行：无死机、无异常重启（串口启动日志计数 = 0）、无配置丢失；全程至少经历 1 次主动断网重入网演练 |
| 门限设置与看门狗兼容性 | 看门狗开启状态下，电流门限、漏电流门限、电压上下限设置均即时生效；每类 ≥20 次，无异常复位或重入网，读回一致且保护/报警按新门限动作；设置响应时延 P95 不劣于 V7.14 关闭看门狗版本实测基线的 120% |
| 协议回归 | 5.4 测试集 F-01 ~ F-19（含边界与异常用例）100% 通过 |
| 目标市场认证 | 按首批出货区域完成 CE RED / FCC 认证 |
| 量产供钥 | 一机一密产线烧录流程可用并通过演练 |

## 四、项目范围

### 4.1 范围内

- 利尔达可变频率模组选型与评审（含型号确定）；
- 通讯板 PCB 重新设计与打样（原理图、Layout、样机）；
- 固件适配：模组 AT 指令层新增实现、入网配置流按可变频率模式重写、量产一机一密、看门狗恢复及门限设置兼容改造；
- 系统测试：功能回归、通信性能、长稳、双频段（EU868 / US915）验证、平台联调；
- 目标市场认证送样与测试（CE RED / FCC，按首批出货区域定优先级）；
- 小批量试产验证与量产放行评审。

### 4.2 范围外（已确认的范围决策）

以下事项经评审确认**不在本期范围**，立项书在此明确记录，防止范围蔓延：

1. **上行报文格式冻结**：本期不改上行数据格式。空开解码器（V3.2）已部署于 ChirpStack / TTN 且线上有存量设备在网，上行报文一个字节不变，平台侧解码器零改动。
2. **车位锁 CL 板暂不跟随**：车位锁硬件（CL 板）当前复用空开软件，本次模组替换以空开主线先行，CL 板跟随下一批切换。固件保留 CL 板编译开关可编译，但不列入本期验证范围。
3. **频段优先级**：第一期只做 EU868 与 US915 两个主力市场频段的完整验证；其余频段（AU915、CN470、IN865、AS923、KR920）复用同一套固件按订单需要出包，不单独排期。
4. **LoRaWAN 协议版本升级与 LR-FHSS/卫星能力**：仅在模组选型时作为选型加分项评估预留，不构成本期交付内容。

## 五、技术方案

### 5.1 现状基线（已核实）

| 项 | 现状 |
|---|---|
| 主控 | GD32F103（GD32F10x 系列），Keil MDK 工程 |
| 模组驱动 | AT 指令抽象层：业务逻辑与指令集通过编译开关分离，现有利尔达、欧创两套指令集实现 |
| 入网方式 | OTAA，Class C（默认），关闭 ADR，固定速率 DR3，固定信道组；入网超时约 120 s 判失败，退避 10 分钟后模组复位重试；模组忙/状态脚等待链最长 15 s + 7 s（新模组适配须消除同类阻塞） |
| 容错机制 | 确认帧重发 3 次；连续 5 次发送失败判离线并清空发送缓冲区（2 KB 环形缓冲，满时丢弃最旧）；热启动关闭；看门狗历史配置窗口约 10 s（当前停用） |
| 业务能力 | 最多级联 10 台空开（地址 0~9）；485 轮询周期 30 s；上报周期可配 300 ~ 36000 s（代码实测口径，注意：更新记录所称"上限 1 天"与代码不符，以代码为准，M1 需对账口径）；变化上报（change_mask）三类事件触发即时上报；485 协议 V1.5；透传指令码 0xEE |
| 遗留问题 | ① 看门狗自 V7.13 起关闭且 V7.14 仍关闭；已获知关闭原因与确保电流、漏电流、电压上下限等门限设置即时生效有关，需复现定位并在恢复后专项回归；② 仓库当前编译开关处于样例模式（演示用共享密钥），量产必须改一机一密 |

### 5.2 硬件方案（PCB 重新设计）

- **选型约束**（M1 里程碑输出，向利尔达书面确认）：
  - 目标区域模组认证报告现成（CE RED / FCC），可缩减整机认证测试项；
  - 封装与管脚尽量兼容现款模组，降低改版深度；同时评估封装兼容的备选型号，留第二货源余地；
  - 书面 EOL（停产）承诺；
  - 优先新一代射频平台（SX126x 代际），为后续协议版本演进留余地；
  - 发射峰值电流与现款电源设计余量核对。
- **改版内容**：模组封装与管脚适配、射频馈线与天线匹配网络重新调测、电源余量复核、烧录与调试接口预留、版本标识丝印。
- **交付物**：更新版原理图、PCB（基于现款《智能空开通讯板原理图 2024-04-01》改版）、打样样机、硬件测试报告。打样目标控制在 2 轮以内。

### 5.3 固件方案

- **AT 指令层**：在现有抽象层内新增新模组指令集实现（第三套），业务逻辑层（级联管理、上报、485 协议）不动。
- **入网配置流重写**：由"关 ADR + 固定 DR3 + 固定信道"改为可变频率模式（标准跳频 + 区域信道计划），ADR 与速率策略按区域在选型评审时定参；EU868 的占空比约束与 US915 的子带规划作为重点核对项。
- **上行格式冻结**：应用层报文结构与 0xEE 透传封包维持 V1.5 口径不变，作为验收硬约束。
- **量产安全**：移除样例模式的默认编译，实现一机一密产线烧录流程（DevEUI 派生或产线注入，方案在 M1 定）。
- **看门狗恢复与门限兼容**：针对 V7.14 关闭看门狗以确保门限设置即时生效的历史问题先复现定位，重点消除超过看门狗窗口的模组/485 阻塞并完善超时与喂狗策略；恢复后必须同时满足看门狗保护有效、门限设置即时生效，不得以再次关闭看门狗规避问题。
- **版本策略**：软件版本升为大版本 V8.0，标识硬件平台变更；EU868 / US915 共用主体，频段以编译配置区分。

### 5.4 测试方案

测试集按固件代码可达行为设计，每条用例对应明确的代码路径与判定标准。**通用前置条件**：空开地址分配后首次手动合闸置位远程控制使能位（现固件硬性前提），之后的远程通断用例才有效；EU868 / US915 两频段各执行一遍功能与通信集，长稳测试按主出货区域频段执行。

**F 功能回归集（F-01 ~ F-19，覆盖全部下行命令与上报路径）**

| 用例 | 测试项 | 判定标准 |
|---|---|---|
| F-01 | 地址编码模式进入/退出（0x00，下行指令入口） | 平台下发 0x00，由通讯板经 485 向空开发送进入/退出命令；两个方向各执行 ≥50 次，LoRaWAN 应答、485 响应与空开实际模式一致（对应 V7.12"概率无效"修复项）；另验证进入后 60 s 自动退出。本用例不以空开本体按键作为进入方式；若现场工艺要求进入模式后逐台按键分配地址，另列现场工艺验证 |

| F-18 | 满级联 | 10 台级联下周期上报、批量命令、F-17 事件上报全项复测 |
| F-19 | 异常帧 | CRC 错、帧长错、非法命令码均不应答不死机 |

**C 通信性能集（C-01 ~ C-06）**

| 用例 | 测试项 | 判定标准 |
|---|---|---|
| C-01 | 冷启动入网 | 连续 100 次，RSSI ≥ -100 dBm 环境成功率 ≥ 99% |
| C-02 | 入网失败退避 | 断网环境下记录入网超时 → 退避 → 重试时序，与现款基线偏差 ≤ ±20%（现款利尔达线约 120 s 超时 + 10 分钟退避） |
| C-03 | 连续发送失败判离线（灰盒：故障注入 + 内部状态观测 + 平台复核） | 通过测试固件故障注入或模组状态脚工装制造发送失败，以 SWD 或测试版串口日志观测 `send_failcnt`、`joinState`、`lwrb_write_count`：第 1～4 次连续失败不判离线；第 5 次在同一失败处理周期内判离线、清空缓冲区并设置 10 分钟重连时间；插入一次成功应清零失败计数；恢复入网后平台无旧帧补发。不得以平台缺帧数代替固件内部发送失败计数 |
| C-04 | 环形缓冲区溢出（灰盒：离线攒包 + 调试串口注入） | 保持 `joinState = 0` 停止缓冲区消费，且不得触发连续 5 次发送失败清缓冲；通过 USART2 调试口注入带序号的 100 字节数据帧，每帧间隔 >50 ms，连续注入 21 帧。按每帧 101 字节（含 1 字节长度）计算，20 帧占用 2020 字节、剩余 27 字节，第 21 帧触发丢弃最旧帧；最终仅保留第 2～21 帧，`lwrb_write_count = 20`、`lwrb_get_free() = 27`，最新帧完整、回绕顺序正确，无死机或越界 |
| C-05 | 弱场梯度 | 衰减器 10 dB 步进扫至链路极限，记录各档丢包率与极限 RSSI，不劣于现款基线 |
| C-06 | 跳频与信道计划 | 按选定模组跳频模式核对信道分布统计与区域信道计划（EU868 默认信道 + RX2；US915 子带与 CHMASK 配置） |

|---|---|---|
| R-01 | 长稳 | 7×24 小时、看门狗开启、10 台级联、周期上报 + 每 10 分钟一次下行混合负载：无死机、无异常重启、无配置丢失；期间至少 1 次主动断网重入网演练 |
| R-02 | 看门狗保护与门限设置兼容性（双满足） | a）主动制造阻塞（如模组侧挂死），确认看门狗复位生效，复位后自动重入网、配置不丢；b）看门狗开启状态下经 0xEE 透传分别设置电流门限、漏电流门限、电压上下限，每类 ≥20 次：无异常复位或重入网，0x05 读回一致，无需重启即生效，并以可编程负载/电压源验证保护或报警按新门限动作；设置响应时延 P95 不劣于 V7.14 基线 120%。不得通过再次关闭看门狗通过测试 |
| R-03 | 重复上下电 | ≥100 次上下电循环，每次正常入网且 flash 参数保持 |
| R-04 | 一机一密演练 | 产线烧录流程实测：多台设备密钥互不相同、与设备一一对应；共享密钥样例模式在量产配置中不可达 |

**基线建档（M1 执行，测试方案的前置交付物）**：对现款利尔达固定频率模组设备同环境实测 P-01/P-02 下行时延、C-01 入网成功率、C-02 退避时序、C-05 弱场极限，形成对比基线；新固件全部对比判定以此为锚。

## 六、进度计划

以立项批准日为 T0，单位为周。总周期 **3 个月（T0+13 周，至量产放行评审）**。本计划为压缩排期，成立前提见 6.1；认证排期为最大外部变量，M1 期间锁定。

### 6.1 压缩前提（四条，任一不成立则总工期相应顺延）

1. **模组预认证**：M1 选型必须落在已取得 CE RED / FCC 模组认证的型号上，整机认证走简化测试项 + 加急通道；
2. **打样一轮通过**：PCB 打样与贴装走加急通道（各约 1 周），目标一轮通过；若需二轮改版，总工期顺延 2 周起；
3. **认证排期前置锁定**：认证机构询价与排期在 M1 期间完成锁定，不等到送样再约；
4. **试产与认证收尾并行**：小批量试产于 T0+10 启动，与认证测试收尾并行推进；量产放行评审以认证报告取得为准，接受试产物料的前置投入风险。

### 6.2 里程碑

| 里程碑 | 时间 | 主要工作 | 交付物 |
|---|---|---|---|
| M1 选型与方案评审 | T0 ~ T0+1 | 模组选型（封装/预认证/EOL/峰值电流/协议版本）、认证机构询价与排期锁定、现款基线实测建档、门限设置与看门狗冲突复现定位（含 V7.14 门限响应基线）、供钥方案定 | 选型报告、技术方案评审纪要、认证排期确认 |
| M2 硬件改版 | T0+1 ~ T0+4 | 原理图/Layout 评审、加急打样与贴装、焊接调试 | 改版原理图、PCB、样机（建议 ≥10 台测试 + 5 台备用，数量待定） |
| M3 固件适配 | T0+1 ~ T0+5（与 M2 并行） | 模组文档到手即开工：AT 层新指令集、入网配置流重写、一机一密流程、看门狗恢复与门限设置兼容改造 | V8.0 固件（EU868/US915）、产线供钥流程 |
| M4 系统测试 | T0+4 ~ T0+7 | 首批样机即到即测：回归、性能、双频段、平台联调、7×24 长稳、问题闭环 | 系统测试报告、问题闭环清单 |
| M5 认证送样与测试 | T0+6 ~ T0+12 | CE RED / FCC 整机加急测试（与 M4 尾部重叠启动） | 认证报告与证书 |
| M6 小批量试产 | T0+10 ~ T0+13 | 试产验证、产线供钥演练（与认证收尾并行，见 6.1 第 4 条） | 试产报告、量产放行评审结论 |
| M7 结项 | T0+13 | 项目总结、量产转入 | 结项报告 |

### 6.3 压缩代价与跟踪要求

- 并行度较常规排期显著提高：固件第 1 周即开工、测试提前介入样机、认证与试产重叠 2 周。相应地，计划对"各环节一次通过"依赖很高——硬件二轮改版、下行实时性调优、认证整改任何一项返工，都会击穿 3 个月线；
- 项目按周粒度例会跟踪；任一压缩前提失守时立即评估基线顺延，不等问题积累。
