## 一、项目背景

### 1.1 公司模组使用现状

公司自研物联网设备的通讯模组存在两条技术路线并行的情况：

1. **欧创固定频率模组**：用于自研智能车位锁设备。该设备系统测试未能通过，欧创模组路线已被验证无法作为公司自研物联网设备的基础平台。
2. **利尔达通讯模组**：公司在固定频率（动物追踪器 LSD4WN-2L817M90 等）和可变频率两类自研设备上均有基于利尔达模组的量产与实测经验，均无明显质量问题。

### 1.2 智能空气开关现状

公司自研智能空气开关（产品型号 SCB100，下称"空开"）当前基于**利尔达固定频率通讯模组**设计，主控为 GD32F103，模组通过 AT 指令驱动。固件按目标市场频段以编译开关出多套版本，现有频段配置覆盖 EU868、US915、AU915、CN470（三个子带）、IN865、AS923（三个子区）、KR920，当前软件版本 V7.14（2026-09-17）。

固定频率模组的使用方式存在两项结构性限制：

- **复用率低**：现固件采用"关闭 ADR、固定速率 DR3、固定信道组"的配置，每个目标频段各出一套固件版本并各做一次认证，市场越多、维护面越宽。
- **规模化受限**：固定信道把设备的发送集中在少数频点上。空开的主打市场在欧洲和北美，其中欧洲 868MHz 频段有每信道 1% 占空比的法规硬约束，设备量增长后，互扰恶化与占空比超标的风险都集中在固定频点上。

### 1.3 市场需求

公司自研智能空气开关设备在欧美市场持续有稳定购买需求，是智慧公寓（SmartBuilding）解决方案的主力设备之一。通讯模组的能力与合规性直接决定该产品线的市场准入与规模上限。

## 二、立项必要性

1. **平台归一是必然选择。** 欧创模组已因车位锁系统测试未通过而退出基础平台候选；利尔达模组在公司多条产品线上验证可靠。通讯模组收敛到利尔达一家，可统一技术支持、供货与认证资产。
2. **可变频率模组提升复用率，配置能力跨项目复用。** 可变频率模组运行标准 LoRaWAN 信道管理，"一区域一固件版本"有机会收敛为一套固件加区域参数配置；本次新增的"频段 / 子带 / 启用信道集"现场配置协议按跨项目通用设计，地磁停车传感器等其余利尔达模组产品线可直接复用（协议预留蓝牙入口，经公司自有配置应用对接）。复用率收益将在选型评审后量化（频段版本数收敛比例、模组驱动层复用比例）。
3. **可变频率能力兼顾入网确定性与规模化合规。** 现有产品在标准多信道计划下入网需在启用信道间轮换，批量安装时入网周期长、占用信道且互相影响，是现场已发生的痛点；本方案保留可变频率模组的信道计划能力作为合规基础（欧洲占空比等法规约束在标准信道计划内满足），并支持对密集部署站点将启用信道收敛为指配频点，缩短入网周期、降低批量上电的信道占用与功耗。该条直接对应欧美市场的稳定订单需求。
4. **团队具备同类适配经验。** 固件模组驱动层已按"业务逻辑与指令集分离"的抽象层设计，2026 年 7 月刚完成一次"新增欧创模组指令集支持"的同类适配，本次替换有成熟的工程路径。

## 三、项目目标

### 3.1 总体目标

将智能空气开关（SCB100）的通讯模组由利尔达固定频率模组替换为利尔达可变频率模组，完成 PCB 重新设计、固件适配与系统测试，通过目标市场认证，达到小批量试产放行条件。通讯板按**同一 PCB、两种贴装**设计：板上预留蓝牙芯片与配套 flash 芯片焊位作为可选配置——客户需要蓝牙时，贴装两芯片并适配蓝牙版本固件与蓝牙工具 App，交付蓝牙状态展示与控制、蓝牙固件升级（OTA）能力，方案与地磁停车传感器蓝牙体系保持一致以利跨项目复用；客户不需要蓝牙时，不做贴片，也不做固件与 App 适配。主线配置（不含蓝牙）为本期必选交付与验收主体，不含蓝牙即完整交付、独立结项。

## 四、项目范围

### 4.1 范围内

- 利尔达可变频率模组选型与评审（含型号确定）；
- 通讯板 PCB 重新设计与打样（原理图、Layout、样机）；
- 固件适配：模组 AT 指令层新增实现、入网配置流调整（默认区域标准信道计划 + 频点现场可配置）、量产一机一密、看门狗恢复及门限设置兼容改造；
- 频点配置能力：经通讯板调试串口实现频点 / 启用信道集 / 子带的现场配置与持久化，配置协议按跨项目通用设计（蓝牙入口本期只做协议预留）；
- 蓝牙功能（可选配置，按订单触发）：**同一 PCB**——本期必做的仅是板上预留蓝牙芯片焊位与配套 flash 芯片焊位（主线订单默认均不贴装，焊位定义所需选型 M1 定）；客户需要蓝牙时，执行贴片（蓝牙芯片 + 配套 flash 芯片）、适配蓝牙版本固件（同一固件主体编译裁剪）、蓝牙工具 App（HKT-BLETools）空开档案与 OTA 配套，交付 5.5 节状态展示与控制、按地磁差分 OTA 评审终版约束实施蓝牙 OTA；客户不需要蓝牙时，不做贴片、不做固件与 App 适配；
- 系统测试：功能回归、通信性能、长稳、双频段（EU868 / US915）验证、平台联调；
- 目标市场认证送样与测试（CE RED / FCC，按首批出货区域定优先级）；
- 小批量试产验证与量产放行评审。

### 4.2 范围外（已确认的范围决策）

以下事项经评审确认**不在本期范围**，立项书在此明确记录，防止范围蔓延：

1. **上行报文格式冻结**：本期不改上行数据格式。空开解码器（V3.2）已部署于 ChirpStack / TTN 且线上有存量设备在网，上行报文一个字节不变，平台侧解码器零改动。
2. **车位锁 CL 板暂不跟随**：车位锁硬件（CL 板）当前复用空开软件，本次模组替换以空开主线先行，CL 板跟随下一批切换。固件保留 CL 板编译开关可编译，但不列入本期验证范围。
3. **频段优先级**：第一期只做 EU868 与 US915 两个主力市场频段的完整验证；其余频段（AU915、CN470、IN865、AS923、KR920）复用同一套固件按订单需要出包，不单独排期。
4. **LoRaWAN 协议版本升级与 LR-FHSS/卫星能力**：仅在模组选型时作为选型加分项评估预留，不构成本期交付内容。
5. **蓝牙可选边界（2026-11-04 公司决策：蓝牙为可选配置能力，按订单触发）**：PCB 为同一块板、仅贴装差异。主线配置（不含蓝牙）为本期必选交付与验收主体——主线通过验收第 1~8 项即满足本项目结项条件，不因蓝牙部分顺延或卡顿而阻塞。客户需要蓝牙 → 蓝牙芯片 + 配套 flash 芯片贴片、蓝牙版本固件适配、蓝牙工具 App 适配全部随蓝牙订单启动与验收（验收第 9 项为蓝牙款放行条件）；客户不需要蓝牙 → 不贴片、不做固件与 App 适配，主线不含蓝牙即完整交付。频点配置的蓝牙入口只要求协议兼容，不作为验收路径（频点配置验收走调试串口）；无蓝牙款固件升级路径 = 产线烧录 / 现场 SWD（与现款一致），蓝牙 OTA 仅适用蓝牙款，LoRaWAN 远程升级不在本期（见第 4 项）；蓝牙网关、蓝牙 Mesh 与 iOS 端适配不在本项目范围。

## 五、技术方案

### 5.1 现状基线（已核实）

| 项 | 现状 |
|---|---|
| 主控 | GD32F103（GD32F10x 系列），Keil MDK 工程 |
| 模组驱动 | AT 指令抽象层：业务逻辑与指令集通过编译开关分离，现有利尔达、欧创两套指令集实现 |
| 入网方式 | OTAA，Class C（默认），关闭 ADR，固定速率 DR3，固定信道组（EU868 启用 3 个默认信道，入网与上行在三频点间轮换）；入网超时约 120 s 判失败，退避 10 分钟后模组复位重试；模组忙/状态脚等待链最长 15 s + 7 s（新模组适配须消除同类阻塞） |
| 容错机制 | 确认帧重发 3 次；连续 5 次发送失败判离线并清空发送缓冲区（2 KB 环形缓冲，满时丢弃最旧）；热启动关闭；看门狗历史配置窗口约 10 s（当前停用） |
| 业务能力 | 最多级联 10 台空开（地址 0~9）；485 轮询周期 30 s；上报周期可配 300 ~ 36000 s（代码实测口径，注意：更新记录所称"上限 1 天"与代码不符，以代码为准，M1 需对账口径）；变化上报（change_mask）三类事件触发即时上报；485 协议 V1.5；透传指令码 0xEE |
| 遗留问题 | ① 看门狗自 V7.13 起关闭且 V7.14 仍关闭；已获知关闭原因与确保电流、漏电流、电压上下限等门限设置即时生效有关，需复现定位并在恢复后专项回归；② 仓库当前编译开关处于样例模式（演示用共享密钥），量产必须改一机一密 |

### 5.2 硬件方案（PCB 重新设计）

- **选型约束**（M1 里程碑输出，向利尔达书面确认）：
  - 目标区域模组认证报告现成（CE RED / FCC），可缩减整机认证测试项；
  - 封装与管脚尽量兼容现款模组，降低改版深度；同时评估封装兼容的备选型号，留第二货源余地；
  - 书面 EOL（停产）承诺；
  - 优先新一代射频平台（SX126x 代际），为后续协议版本演进留余地；
  - 发射峰值电流与现款电源设计余量核对；
  - AT 指令须支持启用信道集 / 子带配置且支持单信道入网（M1 依新模组指令手册逐项核对，不沿用现款模组行为推断）；
  - 蓝牙透传芯片与配套 flash 芯片（蓝牙 OTA 暂存介质）选型倾向与地磁停车传感器同方案（App 既有协议与 OTA 体系直接复用），须核对其与 GD32F103 主控的 UART / SPI 接口、供电与封装尺寸；flash 容量按 M3 差分 OTA 分区设计定（参照地磁评审 ≥512 KB 量级口径）；选型结论用于定义焊位（M1 定）。
  - 认证配置策略：默认按含蓝牙配置送测（配合蓝牙模组模块化认证简化整机项），不含蓝牙出货作为其子集由同一证书覆盖，两种配置的认证方案与费用 M1 与认证机构确认。
- **改版内容**：模组封装与管脚适配、射频馈线与天线匹配网络重新调测、电源余量复核、烧录与调试接口预留、版本标识丝印；蓝牙芯片与配套 flash 芯片电路为**预留焊位**（蓝牙经 UART 接主控、flash 接 SPI 总线，PCB 预留天线净空；主线订单默认均不贴装并标注 DNP）——**同一 PCB 支持两种贴装配置：蓝牙款贴装蓝牙芯片 + 配套 flash 芯片，主线款不贴装，不做单独改版**；两种配置 BOM 与丝印明确区分。
- **交付物**：更新版原理图、PCB（基于现款《智能空开通讯板原理图 2024-04-01》改版）、打样样机、硬件测试报告。打样目标控制在 2 轮以内。

### 5.3 固件方案

- **AT 指令层**：在现有抽象层内新增新模组指令集实现（第三套），业务逻辑层（级联管理、上报、485 协议）不动。
- **入网配置流调整（频点方案折中，2026-11-04 评审确认）**：出厂默认沿用各区域标准信道计划（EU868 三频点、CN470 现行八信道子集、AU915 / US915 现行子带），默认行为与现款一致，保持标准兼容；新增频点 / 启用信道集 / 子带的现场配置能力，配置取值限定在区域标准计划范围内，计划外频率一律拒绝；密集部署站点可选将启用信道收敛为单频点，缩短入网周期、降低批量上电信道占用；跳频能力保留为可选模式。ADR 与速率策略按区域在选型评审时定参；EU868 的占空比约束与 US915 的子带规划作为重点核对项；单频点 / 子带运行要求网络服务器侧信道计划同步配置，纳入交付文档。
- **频点配置协议（跨项目通用）**：本期经通讯板调试串口实现配置读写与持久化；协议按"频段 / 子带 / 启用信道集"三要素设计并预留蓝牙入口兼容，后续由带蓝牙模组的产品项目（如地磁传感器，经公司自有配置应用）直接对接复用。
- **蓝牙状态展示与控制（可选配置，随蓝牙订单启动适配）**：客户有蓝牙订单时，主控固件以编译开关启用蓝牙帧服务（帧协议沿用 HKT-BLETools shared/protocol/app-frame.md），经 UART 对接蓝牙芯片；状态读取与控制下发全部映射固件既有能力（清单见 5.5 节），不新增业务逻辑；远程通断"首次手动合闸置位使能"的安全前提原样保留，蓝牙路径不得绕过；蓝牙通道与 LoRaWAN 下行、485 轮询的并发互斥策略在适配启动时的设计评审定，避免叠加出 P-02 同类阻塞。蓝牙服务以编译开关裁剪：无蓝牙配置不编译蓝牙服务，主流程、下行处理与看门狗行为不受任何影响；固件上报配置类型字段（复用版本查询命令携带），产线、平台、App 三方可辨识设备形态。无蓝牙订单时本项不投入开发。
- **蓝牙 OTA 升级（可选配置，仅蓝牙款，随蓝牙订单启动；按地磁差分 OTA 评审终版约束）**：采用"暂存区 + 整包校验 + 失败回退 + boot 最小化"双区升级思路，评审 P0 六条全部为强制项：断电变砖窗口防护、分区表地址口径一致、底包内容级校验、暂存介质硬件前提核实、boot 区软件禁写全路径地址检查（含 APP 侧 Flash 驱动统一封装）、boot 升级只进产线且 App 侧拒绝含 boot 区镜像；升级确认采用通讯读回版本号口径（空开复用既有版本查询命令），App 验收闭环（重启 → 重新广播 → 重连 → 读版本比对 → 基本功能可用）为强制流程，进度 100% 不算成功；传输在既有 bootload 帧协议上演进（整包校验字段、断点续传、错误码上报），搬运与校验期间喂狗；GD32F103 的分区表、暂存介质（配套 flash 芯片）与差分合成位置等设计项在蓝牙订单启动时出方案设计文档评审定稿（对应地磁评审第五节待确认项逐项落位），无蓝牙订单时本项不投入。无蓝牙款升级路径 = 产线烧录 / 现场 SWD，与蓝牙 OTA 解耦。
- **上行格式冻结**：应用层报文结构与 0xEE 透传封包维持 V1.5 口径不变，作为验收硬约束。
- **量产安全**：移除样例模式的默认编译，实现一机一密产线烧录流程（DevEUI 派生或产线注入，方案在 M1 定）。
- **看门狗恢复与门限兼容**：针对 V7.14 关闭看门狗以确保门限设置即时生效的历史问题先复现定位，重点消除超过看门狗窗口的模组/485 阻塞并完善超时与喂狗策略；恢复后必须同时满足看门狗保护有效、门限设置即时生效，不得以再次关闭看门狗规避问题。
- **版本策略**：软件版本升为大版本 V8.0，标识硬件平台变更；EU868 / US915 共用主体，频段与"含 / 不含蓝牙"配置均以编译配置区分，同一固件主体覆盖全部出货形态。

| 上报周期设置 | 0x01 | 边界与 F-02 一致（0 停报 / 300 s 下限 / 36000 s 上限） |
| 地址编码模式进入 / 退出 | 0x00 | 60 s 自动退出行为保留 |
| 门限设置（电流 / 漏电流 / 电压上下限等） | 0xEE 透传 485 写帧 | 组包规则与平台侧一致；与 R-02b 看门狗开启口径同验 |

## 六、进度计划

以立项批准日为 T0，单位为周。总周期 **3 个月（T0+13 周，至量产放行评审）**。本计划为压缩排期，成立前提见 6.1；认证排期为最大外部变量，M1 期间锁定。

### 6.1 压缩前提（四条，任一不成立则总工期相应顺延）

1. **模组预认证**：M1 选型必须落在已取得 CE RED / FCC 模组认证的型号上，整机认证走简化测试项 + 加急通道；
2. **打样一轮通过**：PCB 打样与贴装走加急通道（各约 1 周），目标一轮通过；若需二轮改版，总工期顺延 2 周起；
3. **认证排期前置锁定**：认证机构询价与排期在 M1 期间完成锁定，不等到送样再约；
4. **试产与认证收尾并行**：小批量试产于 T0+10 启动，与认证测试收尾并行推进；量产放行评审以认证报告取得为准，接受试产物料的前置投入风险。

### 6.2 里程碑

### 6.3 压缩代价与跟踪要求

- 并行度较常规排期显著提高：固件第 1 周即开工、测试提前介入样机、认证与试产重叠 2 周。相应地，计划对"各环节一次通过"依赖很高——硬件二轮改版、下行实时性调优、认证整改任何一项返工，都会击穿 3 个月线；
- 项目按周粒度例会跟踪；任一压缩前提失守时立即评估基线顺延，不等问题积累。
- 蓝牙为可选配置、按订单触发（V1.8 / V1.9 公司决策）：本期主线不含蓝牙即完整交付；蓝牙贴片（蓝牙芯片 + 配套 flash 芯片）、蓝牙固件适配、蓝牙工具 App 适配全部随订单启动，其供货、OTA 双区方案、App 排期任何返工只影响蓝牙订单交付窗口，**不威胁主线 3 个月线**。
